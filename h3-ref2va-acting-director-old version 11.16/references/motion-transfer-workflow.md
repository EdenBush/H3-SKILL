# 动作迁移工作流：从参考视频到一条通过的成片

这份文件把"参考视频 → 新主体"的整条工作流收进来。它管的是**流程与判据**；六段式字段怎么写仍以 `SKILL.md` 与 `ref2va-video-reference.md` 为准。

核心原则一句话：**先分析动作，再动笔；一次只用一个动作源；把模型容量花在动作保真上，不要花在复杂场景上。**

---

## 一、入口判定

**该走这条路**：把某段参考视频里的舞蹈 / 手势 / 动作组 / 位移 / 运镜，搬到另一个主体身上。"让我的角色跳这个舞"、"让人偶抄这几个手势"、"把这个运镜搬到我的产品上"。

**不该走**：

| 情况 | 去哪 |
|---|---|
| 只要参考视频的**画面风格**、没有动作 | 风格参考，不是动作迁移 |
| 要剪辑 / 延长参考视频本身 | 视频编辑 / 延续 |
| 真实的、可识别的私人，且无授权 | 拒绝——H3 使用政策禁止冒充 |
| 没有视频、没有关键帧、没有姿势图 | 纯文字编排没有可迁移源；退回 T2VA 或 I2VA |
| 需要超过 15 秒的**连续**动作 | 分段（见第六节） |

---

## 二、开工前的六项确认

1. **动作源视频**（Ref2VA 路线必需）——最佳 4–15 秒、主体清楚、机位静或简单；超过 15 秒要先切窗口
2. **目标主体**——角色图或精确文字描述；**体型差异要当场指出**（吉祥物 vs 人类舞者），它决定可行性
3. **输出规格**——比例与时长（默认跟随参考窗口，夹在 4–15 秒）
4. **机位政策**——`static camera`（默认、推荐）或 `copy reference camera`
5. **场景政策**——默认简单中性场景；**复杂场景会吃掉动作保真度**，用户坚持时要说明这笔交易。**若用户要求"1:1 复刻（只换人）"，场景就不是自建而是照搬参考**——两套写法互斥，见 `ref2va-video-reference.md` 3.0 的复刻态 / 重建态对照表
6. **音频政策**——静音 / 只有音效 / 配乐方向；是否借参考视频的节奏。**复刻态要特别注意：原曲在原音轨里，排除音轨就必须同时把 `non_diegetic_music` 写成 `N/A`，不能一边排除一边说"配乐保留"**

---

## 三、先分析，再写提示词

### 参考视频侧

- 动作类别：全身舞蹈 / 上半身手势 / 位移行走 / 面部表演 / 纯运镜
- 主体景别：全身 / 半身 / 特写
- 速度：慢 / 中 / 快；节奏是稳定还是重音驱动
- 遮挡、道具、与其他人的互动
- 机位：固定 / 摇 / 跟 / 环绕，以及动作占画面多大比例

### 复杂度分级（决定时长与是否分段）

| 级别 | 特征 | 生成策略 |
|---|---|---|
| **S** | 慢、单平面、无遮挡（挥手、点头、摇摆、慢走） | 单次生成，可到 15 秒 |
| **M** | 多肢体协同、中速（一段舞句、跳跃落地） | 单次生成，建议 ≤10 秒 |
| **L** | 旋转、快速脚步、技巧动作、强遮挡 | 拆成 2 段以上、每段 ≤8 秒，或请用户简化 |

### 目标主体侧

- 与参考主体的体格兼容性（人形 / 四足 / 物件）
- **3–5 个必须在每一帧活下来的身份锚点**（轮廓、颜色、标志性配件）
- 哪些参考动作对这个体格在物理上不成立——当场标出来

### 结论

一段话：可行 / 简化后可行 / 不可行，并说明为什么。

## 四、Motion Beat Sheet（分析产物，不是提示词内容）

把参考动作分成 **1–4 个节拍**，每拍一个可读动作，带时间码：

```text
0.0–2.5s: weight shifts left, both arms rise
2.5–5.0s: spin, arms pull in
5.0–7.5s: two steps back, shoulder drops
```

三条硬约束：

1. **节拍必须来自参考视频里真实存在的动作，不许编。** 这是分析记录，写给人看的。
2. **15 秒内不超过 4 拍。**
3. **Beat Sheet 默认不进提示词**——它用于规划时长、判断分级、以及事后对照"哪一拍丢了"。

> **与"不打时间轴"的关系**：默认不写时间码（见 `ref2va-video-reference.md` 6.0）。**只有一种例外**：成片出现"节拍漂移"（拍与拍之间的相对时长错了），才把时间窗写进提示词，而且写成**指向动作来源**的形式，不是动作细节：
> `The target performs the motion of <Video 1> from 0.00 to 2.50 seconds, then from 2.50 to 5.00 seconds, following that tempo exactly.`

---

## 五、提示词构造：动作本身也要有 `<Subject N>`

这是动作迁移最有用的一招——**给"动作"单独开一个 Subject**，让它和"人"分开被引用：

```text
subject_definitions:
<Subject 1> is the target character from <Picture 1> ... (appearance only)
<Subject 2> is the dance routine performed in <Video 1>, including its step sequence, timing and tempo.
```

好处有三：动作从"人的属性"变成"可引用的实体"，多主体时不会互相污染；`attribute_transfer` 有了明确指出发点；换人时只改 `<Subject 1>`，动作那行不动。

配合写法：

- `summary` 前缀任务类型标签：`[reference generation]`，然后一句话写"谁、做什么、来自哪个标签"
- `retention_analysis`：目标外观 `fully_preserved`；动作 `attribute_transfer` 从参考表演者迁到目标；抄机位时才给 `<Video N>` 写 `fully_preserved`（`camera path` + `pacing`）
- `detailed_description`：先风格句，再 `[Shot 1]` 且**不带时间戳**；**只说动作来自哪里，绝不重述舞步**；把增量写满——场景、机位政策、主体站位、声音
- 篇幅：生成类任务 **350–500 英文词**
- 语言：字段英文；台词 / 歌词 / 画面文字保留原语言，放 `<d>` 或引号内

---

## 五·补、多主体迁移：每人一张制作卡 + 两类已知冲突

参考视频里有两个以上的人，且成片里也要两个以上时，光写"谁演谁"不够。

**每人一张制作卡**，七项缺一项就会出现"两个人长得像、站位飘、动作打架"：

| 项 | 内容 |
|---|---|
| 身份 | 脸 / 发型 / 标志物 |
| 服装 | 主色 + 轮廓 + 配件 |
| 起始站位 | 画面左右、前后、距离 |
| 道具归属 | 谁拿手机 / 谁拿杯子，不能含糊 |
| **动作界限** | 这一份运动属于她，另一份不属于她 |
| 说话人 ID | `(S1)` / `(S2)`，跨镜头不变 |
| 参考来源 | 哪张图给身份、哪段视频给动作 |

差异要一眼可辨——不要写"两个穿深色外套的人"。

**一条优先级**：官方实践里「一个人一个主要动作」比「两人同时各做一件不同的事」可靠得多（one interaction beats several simultaneous movements）。后者属于高难配置，必须同时具备**归属 + 站位锁 + 动作界限**，并提前准备好"拆片各自单独生成"的 B 计划。

**两类已被列为冲突的情况**：

- **motion conflict** —— 两个来源给出互不兼容的身体动作。修法：砍到一个动作源，或拆片段。
- **camera conflict** —— 提示词要固定机位，参考视频却给手持晃动。修法：`strictly_avoided` 里排除 `camera path`，并在镜头描述里写 `The camera holds a static shot throughout`。

另外：`<Video N>` 代表的是整片级关系；如果复用视频里的人物作为可见内容，那个**人**仍然必须单独定义为 `<Subject N>`，不能默认 `<Video 1>` 就是那个人。

## 六、分段与接续

L 级或超过 15 秒：

1. 在**动作停顿处**切，不要在动作中段切
2. 每段 Ref2VA 用**完全相同的 subject_definitions**
3. **衔接靠尾帧**：上一段通过后的最后一帧，作为下一段的 `<Picture N>` 首帧锚点（Ref2VA + 关键帧混合）
4. 每段参考视频必须**按时间区间裁开喂**，否则每段都从头重演（见 `ref2va-video-reference.md` 第四节）

**一次生成里绝不混用两条参考视频——一个动作源。**

---

## 七、生成与复查

- 模型 `MiniMax H3`；时长 = 计划窗口（4–15s），比例 = 计划比例
- **第一遍只出 768P**（短边 768），动作通过后再上 2K
- 一次生成对应一个计划片段；不要整条链一起批量试
- **每次重试只改一个变量**

### 复查清单

| 项 | 判据 |
|---|---|
| 动作保真 | 参考动作可辨认；Beat Sheet 的每一拍按序出现；速度对得上 |
| 覆盖完整 | 没有哪一拍被悄悄丢掉；最后一拍落在时长之内 |
| 身份 | 目标锚点每帧都在；没有从参考表演者身上漏过来的特征 |
| 身体完整 | 不多肢、不熔关节、不僵肢、服装不突变 |
| 机位政策 | 说固定就固定；说复制就与参考路径一致 |
| 场景纪律 | 背景没有偷走移动主体的细节预算 |
| 音频 | 符合约定；音乐速度贴合动作 |

每项判 通过 / 部分（指出哪一拍）/ 失败。部分与失败都要**指名原因**再进下一步。

---

## 八、重试：先修最便宜的那一层

| 症状 | 第一手 | 第二手 |
|---|---|---|
| 动作被忽略 / 被换成通用动作 | `retention_analysis` 写清迁什么（步序、时机、速度）；`[Shot 1]` 第一句重申动作来源 | 缩短时长；减少节拍 |
| 拍与拍之间速度漂 | 给每一拍补时间码（指向来源的时间窗） | 减少拍数；缩短时长 |
| 目标身份中途漂移 | 给目标的 `<Subject N>` 补 1–2 个更强的锚点 | 加一张目标图作为 `<Picture N>` 关键帧锚 |
| 熔肢 / 多肢（L 级） | 在动作停顿处分段；场景简化成纯背景 | 要求"同一套动作的放慢版本" |
| 该固定机位却动了 | 在镜头描述里加 `The camera holds a static shot throughout` | — |
| 场景抢了焦点 | 把场景剥到中性背景 | — |
| 链上某一段失败 | 只重生成那一段，用同一个上游尾帧 | — |

**同一层失败两次后不要盲试第三次**——向用户提简化方案（更短窗口、更少拍、更简单的动作）。

---

## 九、没有参考视频时的降级路线

| 手头素材 | 模式 | 说明 |
|---|---|---|
| 参考视频 + 目标图 | **Ref2VA**（首选） | 动作保真最高 |
| 参考视频 + 纯文字目标 | **Ref2VA** | 结构相同，主体在 `subject_definitions` 里用文字定义 |
| 目标图 + 文字动作描述 | **I2VA** | 动作靠文字，保真取决于描述质量 |
| 起始姿势图 + 结束姿势图 | **FL2VA** | 单镜头，描述两姿势之间的路径 |
| 只有结束姿势图 | **L2VA** | 罕见，用于"必须落在这个收势上" |
| 完全没有素材 | **退回** | 不是迁移任务 |

---

## 十、边界

只迁**动作**，不迁身份：不要把参考表演者的脸、身体、肖像搬到目标上；**不要用来让真实私人做出他们没做过的行为**。纯风格迁移、视频编辑、超过 15 秒不分段的需求，都不属于这条路。
