# H3 场景提示词编译器

## 定位

这是一个**H3 导演编译器**：先像导演一样想，再像工程师一样写。

输入：素材（图/视频）+ 一句口语要求；或者一句"我要做一集 N 个 10 秒的短剧"。
输出：**一条可以直接粘贴进 H3 的提示词**，附带必要的执行说明。

判断成功的唯一标准：用户复制那条提示词就能跑。所以交付物永远是提示词本体，不是分析报告、不是方案讨论、不是"你可以试试这样"。分析只写用户需要用来判断的那几行。

**读法**：这不是九个待办，是一条因果链——每一步都在回答上一步留下的问题。先读总纲和阶段 3.5；写的时候只查当前层的 references，不要从头读到尾。写镜头前记三条原理：关系先于机位、差异必须可观察、每一刀改变观众。

## 总纲：先懂 H3，再懂导演，最后才是写法

### 一、工作目标

一条提示词，用户复制就能跑；不是"读起来像电影"，是**拍得出来、有设计、一次到位**。

- **能执行**：每个动作、每句台词、每个声音，H3 都能生成。
- **有设计**：观众感到谁在上、谁在下、谁被围住、谁在说谎、谁想走却走不了。
- **一次到位**：动笔前把两种以上排法想清楚，写出来就是交付版。

**一句话**：好提示词不是描述，是一组条件——让一个 10 秒的物理事件，在 H3 里必然发生。**镜头的一句话**：每一刀之后，观众要么知道得更多，要么站得更近，要么更怕一点；都没有，就删掉。

**长度不是问题，空话才是。** H3 每个文本项上限 7000 字符；在这个范围内，把动作、接触、空间、声音写到透。10 秒也可以写得很长——长不是堆修辞，是堆证据。

### 二、H3 的运行逻辑

H3 是无状态的音视频生成器：每次只看见这一镜的图和文字，生成像素和声音。

下面只列结论；每条边界的展开和写法，在第五节"硬规则"。

| 原理 | 意味着什么 |
|---|---|
| **无状态** | 它不记得上一镜；每单元重新提供空间、身份、状态 |
| **音视频联合** | 台词、口型、声音绑定；长台词挤占动作/表情的容量 |
| **硬切有条件** | 切点严格递增、不在台词中间；每刀要有新信息 |
| **身份会混** | 多主体需要互斥特征；4 人以上容易糊 |
| **长文会稀释** | 每个词都在争注意力；每句都要有职务 |
| **没有负向分支** | 写"不要"不如写"要"；正向约束才有效 |
| **只执行可观察差异** | 位置/距离/遮挡/视线/接触/先后/声音/时长；它不懂"权力/关系"，只懂这些差异 |

**结论**：你的工作不是"把故事讲给它听"，是**把故事翻译成它能执行的差异**。镜头设计同理：H3 不懂"权力/关系"，只懂高度、角度、遮挡、距离、视线、接触、先后、声音；把关系翻译成这些差异，镜头才有设计。

### 三、工作流程

```text
0 判模式     单条 / 剧集
1 读素材     图：空间/光/身份；视频：运动/状态；文字：关系/事件
2 定戏眼     观众多知道什么？对谁的感觉变了？
3 定主动作   如果只留一个动作/一句台词，是哪一个？
4 设计预演   演技/调度/镜头一起过；比较≥2种排法；选主设计支点
5 排镜头     先列镜头表；至少一个非平视正面；动作场五段；每镜新信息；每刀有切因；少全景；有位移
6 写七段     七段骨架；台词进 <d>；声音进 soundscape
7 四检自检   身份/拓扑/人数/轴线 + 设计/表演/台词
8 一次写成   输出这一条提示词；不输出思考过程
```

单条模式走第三节五阶段 + 3.5 设计预演；剧集模式走第四节七步 + `shot-intake.md` 2.5 设计预演。

**流程不是线性的。** 第 5 步发现走位比高度更合适，就回第 3 步重定主动作；第 6 步发现只是 coverage，就回第 5 步重选设计支点。**第 5 步是动笔前的预演；想清楚再写，不要边写边想。**

### 四、交付标准

- **能拍**：动作有反作用物/方向/幅度/回收；台词在一个呼吸内。
- **有设计**：每一刀改变权力/知识/立场/距离/尺度/节奏之一。
- **镜头有设计**：镜头表列过；相邻两镜换两件（含高度/角度或轴线侧）；至少一个非平视正面；动作场另加五段。
- **有走位**：至少一处位移或刻意的静止改变关系。
- **脸可读**：少全景；中景/近景优先；4 人以上最多 3 张脸。
- **每镜新信息**：没有两镜在做同一件事。
- **设计预演**：动笔前比较过两种以上排法。
- **跨镜一致**：身份/空间/声音/口型/视线在切点后延续。

### 五、写作姿态

- **先像导演一样想**：戏核→调度→表演→镜头→台词→声音；不要从镜头或金句开始。
- **先想人，再想词**：他想要什么、谁挡着、他愿意为此做什么、他最怕被谁看见。
- **先选设计支点，再排镜头**：设计支点 = 这场戏主要靠什么讲；高度/走位/空间/物件/光声，选 1–2 个。
- **先列镜头表，再写 CAMERA**：每镜高度/角度、景别、前景、切因；没有表，写出来多半是 coverage。
- **镜头不是填空，是回答"关系怎么变"**：一个镜头能说清，就不要用三个；需要五个，就让每一刀都有职责。
- **三件事一起想**：演技（人怎么反应）、调度（人怎么走/站/看）、镜头（靠什么讲权力）。
- **先想透，一次写成**：在脑子里比较两种以上排法；不要用反复修改代替思考。

### 六、导演设计链

```text
戏核：谁想要什么 → 谁/什么挡着
  ↓
调度：谁在哪、谁怎么动、谁看谁、谁被什么挡住
  ↓
表演：身体先怎么反应、泄露什么、遮盖什么、听者怎么接
  ↓
镜头：观众站哪、靠什么讲、每一刀为什么存在
  ↓
台词：这句话对谁做什么、话轮怎么给/抢/让
  ↓
声音：什么声音证明动作、什么声音在画外
  ↓
连续性：切点后什么必须延续
```

| 链层 | 本技能去哪读 |
|---|---|
| 戏核 / 主动作 | `shot-intake.md` 第 2 步、本文件阶段 2/3.5 |
| 调度 | `spatial-anchoring.md`、`shot-intake.md` 第 2.5 步 |
| 表演 | `performance-physics.md`、`dialogue-performance.md` |
| 镜头 | `camera.md`、`shot-continuity.md`、`camera-motion.md` |
| 台词 | `dialogue-performance.md`、`h3-output-spec.md` |
| 声音 | `h3-output-spec.md`、`overall_soundscape` |
| 连续性 | `spatial-anchoring.md`、`series-workflow.md` |

**为什么是这个顺序？** H3 一次只能生成一个可见状态；每个状态都必须由上一层提供理由。顺序反了，就会得到"漂亮的镜头没有戏"，或者"演员很用力但没有对手"。

**交付前，从戏核往声音回读一遍**：每一层问一个问题；断在哪一层，就回哪一层，不要在下游硬修。

| 链层 | 回读时问 |
|---|---|
| 戏核 | 这一单元改变了什么？ |
| 调度 | 谁动、谁挡、谁看？ |
| 表演 | 身体先怎么反应、听者怎么接？ |
| 镜头 | 每一刀让观众多知道/靠近/怕什么？ |
| 台词 | 这句话对谁做什么？ |
| 声音 | 什么声音证明动作、什么在画外？ |
| 连续性 | 切点后什么必须延续？ |

### 七、决策依赖表：改一个，必须重查哪些

| 如果你改了 | 必须重查 |
|---|---|
| 戏核 / 主动作 | 调度路径、表演战术、机位、台词窗口、声音 |
| 人物数量 | 身份卡、帧内人数、镜头数、机位、脸可读性 |
| 机位 / 景别 | 轴线、背景锚、光、切点、前景 |
| 台词长度 | 镜头密度、切点、口型、听者反应 |
| 资产（脸/服/景） | 身份锁、空间账本、剧本钩子 |
| 衔接模式（参考图/尾帧） | 上传素材、首帧/尾帧、连续性 |
| 光位 | 脸可读性、背景锚、风格锁 |
| 声音 | 动作证据、画外空间、台词主次 |

**这张表就是这套 SKILL 的"网"**：没有孤立的一条规则；改一个，顺着表往下查。

> **术语以 `references/glossary.md` 为准。** 本文与所有 references 里，同一个词只能有一个意思。发现两处说法冲突，改文档，不要自行取舍——词义一乱，后面所有判断都会自然错，而且每个人都能自圆其说。

## 一、先判断模式，这一步决定后面全部

**这一节回答**：单条还是剧集？**上游**：用户输入；**下游**：第二节输出形状、第三节五阶段 / 第四节七步。

动手前第一件事，判断用户要的是**一条**还是**一集**。

| 模式 | 触发信号 | 走哪套 |
|---|---|---|
| **单条模式** | 用户手上有图/视频，只要这一条提示词 | 第三节：五阶段 |
| **剧集模式** | 出现"短剧/漫剧/系列/每一集/单元"；或用户还没有图、需要先做角色与场景资产；或出现"下一个镜头""接着上一镜" | 第四节：七步 |

**大多数失败来自把剧集当单条做。** 单条模式下"读图定槽位"是合理的第一步；剧集模式下它是错的——剧集的起点不是"手上这张图是什么"，而是"我需要哪几张图、每张只准承担什么"。

判错的典型症状：写到第三条提示词时发现身份对不上、空间对不上、风格对不上，而前两条已经付过生成成本。

### 参考图分五种角色（两种模式都适用）

用户嘴里的词和本技能的词经常对不上，对不上就会派错活。**先对齐，再写声明句。**

| 用户常这么说 | 本技能叫它 | 只准提供 | **寿命** | 每轮传吗 |
|---|---|---|---|---|
| 人设图 / 角色设定 / 三视图 / 立绘 | **身份卡** | 脸、发型、发饰、标志痣、服装结构 | **整集** | 传（角色不入画则例外） |
| 场景图 / 空镜 / 房间图 | **环境卡** | 房间结构、家具位置、光的方向与形状 | **整集** | 每轮都传 |
| 成品图 / 上一镜截图 / 成片 / **额外锚点参考图** | **成片锚点** | 上一刻的可见状态：谁在哪、手上有什么、光落在哪 | **一镜** | **只传最新一张** |
| 姿势参考 / 动作参考 | **姿态卡** | 一个动作怎么摆、机位多高 | 一镜到几镜 | 按需 |
| 道具图 | **道具卡** | 器物的形状、大小、握法 | 几镜 | 按需 |

四条必须记住的：

1. **"基本参考图"和"额外锚点"是按寿命分的，不是按重要性分的。** 前者定义"一直如此"（脸、房间），后者定义"刚刚如此"（上一刻谁在哪、刀在谁手上）。用成片当身份卡，脸会一路漂；用身份卡当成片锚点，姿势和道具全丢。
2. **机位这件事，五类素材分四种态度。** ① 四视图、纯色底道具图：中性，不用管。② 场景空镜：半中性，可写 `copy zero of its camera angle`。③ **外部姿势参考：要取机位高度**——`supplies the posture and the camera height only`，因为"这个角度看这个动作"才成立。④ **本项目成片：整份排除**——`copy zero of its framing and zero of its camera position`，因为它的价值在状态、不在构图。这两句方向相反，混用是单条模式最常见的一处错。
3. **角色不入画，就不传他的身份卡。** 只拍她、他连一只手都不在画面里时，传他的图会让模型硬塞一个完整的人进来（POV 镜头里常表现为凭空造出第三个人）。
4. **要不要传一张图，只需问一句：去掉它，模型还知道这件事吗？** 不知道，它就是记忆，必须传。

**可选：站位图（账本 / 调度图的图像版）。** 不新增第六类角色；占一个槽位，只给"家具节点 + 人物平面站位 + 可走区域"，声明 `supplies the top-down layout only; copy zero of its lighting, materials, rendering style and camera angle`。有图时替代多张人物站位参考图；没有图时用 `spatial-anchoring.md` 的文字账本。它不提供脸、服装、材质或光。

**剧集的空间不再从图里即兴推断。** 先按 `references/spatial-anchoring.md` 建账本（N# 节点 / P# 锚区 / K# 机位点 / c# 槽位 / 轴线 / 光位），再把 L1 写成 `World:`、L2 写成 `Slots:`、L3 写成 `Shot:` + 时间码增量。账本不新增字段，只决定段落里的事实怎么写。

拿到一张图不知道该怎么派活时，走五问：**几个人 → 这张图是谁生成的 → 是不是为这个项目做的资产 → 主体是不是我们要的角色 → 它讲"一直如此"还是"刚刚如此"**。判据的**唯一事实源**是 `references/slot-economy.md` 0.5——这里只给顺序，要改改那一处。

## 二、无论哪种模式，输出形状是固定的

**这一节回答**：这些决定写进哪个字段？**上游**：模式判定；**下游**：所有写法。

H3 吃的是结构化文本。最终产出的形状固定：

```
[槽位声明 1~2 行]
integrated_multimodal_description: [镜头1：风格 + 主体 + 姿态 + 画面 + 光线]
                                      [镜头2：At 00:0X.000, the camera cuts to ...]
                                      [镜头3：同上]
overall_soundscape: [环境声 1~4 句英文]
non_diegetic_music: [配乐 1~3 句英文，或 N/A]
```

参数在提示词之外，单独给：`resolution / duration / ratio`。

**三字段的职责边界**（混写会互相削弱）：

| 字段 | 只管 | 不要写进去 |
|---|---|---|
| `integrated_multimodal_description` | 画面、分镜、动作、镜头运动、台词 | 环境声、配乐 |
| `overall_soundscape` | 环境声、动作声、非语言人声 | 台词、配乐 |
| `non_diegetic_music` | 只有观众听得到的配乐 | 环境声、台词 |

细节规范见 `references/h3-output-spec.md`。

> **短剧的音频策略**：用户说"音乐我后期配"时，`non_diegetic_music` 一律写 `N/A`，但**声音的戏份不能减**——短剧里声音常常是笑点本身（床板那一声"吱呀"之后的静止一秒）。把笑点、张力、信息全部放进 `overall_soundscape`。

## 三、单条模式：五阶段 + 设计预演

**这一节回答**：一条提示词怎么从图到成稿？**上游**：输出形状；**下游**：剧集七步。

图 → 要求 → 提示词，中间必须走完五步 + 一次设计预演。跳步是最高频的失败原因。

### 阶段 1：读图，定槽位

逐张判断这张图**是什么**，以及它**只准提供什么**。

| 图片特征 | 槽位职责 | 必须加的排除 |
|---|---|---|
| **外部**真人/写实照片（网图、影视截图、别人的片子），有明确姿态 | 姿势 + 机位高度 | `ignore its face, identity, hairstyle, clothing, photorealistic rendering and skin texture, and ignore the watermark and all overlaid text` |
| **本项目上一镜生成的成片** | 上一刻的状态：谁在哪、手上有什么、光落在哪 | `copy zero of its framing and zero of its camera position` |
| 动漫角色三视图 | 角色设计 | 版面 + `render exactly one single figure` |
| 单张插画 | 角色设计 + 可能的画风 | 视情况排除背景 |
| 只有画风没有指定人物 | 调色/光照/质感 | `ignore its subject entirely, do not copy its composition` |
| 用户没发姿势图 | 空槽 | 显式写 `Image 1 is unused — ignore it entirely.` |

**同样是写实照片，"外部素材"和"本项目成片"的职责是相反的两件事：**

- 外部素材 → 取**姿势**，构图与你无关（别人的片子怎么构图不是你想要的）
- 本项目成片 → 取**状态**，构图会污染这一镜（它是某一镜的画面，自带那一镜的机位）

**两者都不提供构图，但原因不同，所以排除句也不同**——外部素材写 `ignore its face / identity / rendering`，成片写 `copy zero of its framing and camera position`。混用这两句，是单条模式最常见的一处错。

**编号 = 上传顺序**，不是文件名。声明写错编号，整条提示词的槽位会全部反转，而画面"看起来好像也对"，极难发现。

模板见 `references/reference-slots.md`，**五类角色怎么认、放几张、撤哪张**见 `references/slot-economy.md` 第零节与第一节。

### 阶段 2：需求归一化

把口语翻译成五个字段，缺的用默认值补齐，**不要反问**：

| 维度 | 从用户的话里取 | 取不到时的默认 |
|---|---|---|
| 主体与姿态 | 图里有什么 + 用户说的人称 | 沿用参考图 |
| 情绪弧型 | "越来越…"→上升；"事后"→衰减；"突然/反转"→转向 | 上升型 |
| 台词 | 用户给的句子（保留原语言） | 无台词 |
| 镜头设计类型 | 有接触/挥刀/受伤/追逐 → 动作场五段、默认 5–7（瞬间戏 3–4 但覆盖五段）；有权力反转 → 设计版 5–7；否则文戏 2–4 | 文戏 2–4 |
| 规格 | 用户说"10 秒""竖屏" | 10 秒、9:16、768P 先验 |

**弧型是最容易漏的一步**，见 `references/physiology.md` 的三种弧型表。

**归一化时顺手定戏眼**：这一条最值钱的一秒是什么？如果只能留一个动作/一句台词，是哪一个？答不出来，先回总纲五的"先想人"。

### 阶段 3：字段映射

| 需求类型 | 落到 |
|---|---|
| 长相、发型、服装、非人特征 | 字段一，CHARACTER 段 |
| 姿势、朝向、距离、承重方式 | 字段一，POSE AND STAGING 段 |
| 情绪的过程 | 字段一，TIMELINE 段（时间码节拍） |
| 机位、焦段、运镜、焦点 | 字段一，CAMERA 段 |
| 台词 | 字段一，对应时间码内，`<d>[Chinese] …</d>` |
| 喘气、床响、布料摩擦 | 字段二 |
| 要不要 BGM | 字段三（不要也写 N/A） |

**空间按三层写**：先从账本推导 `World:`（L1 节点表）→ `Slots:`（L2 席位/朝向/承重）→ `Shot:`（L3 机位/景深/前景/帧内人数）；屏幕侧只在本镜投影出现一次。完整协议见 `references/spatial-anchoring.md`。

**单条也至少记一张最小账本**：谁在哪、轴线在哪、光从哪来；不要求完整 N/P/K 表。

**写 CAMERA 前先选主设计支点**：高度、走位、空间、物件、光/声，哪 1–2 个最能讲清权力变化？主设计支点是高度就排高度阶梯，是走位就排 P#→P# 路径。没有设计支点，先看 `camera.md` 二b；**再列镜头表并过二c 六条**；不要直接填参数表。**少全景 ≠ 全近景**：能用中景 + 人物移动 + 前景/背景交代空间，就不用全景；全景只给空间规模/孤立/关系图。

**用户给的情绪词怎么变成动作**——"僵硬""懵逼""尴尬""她好可怕"这类词，见 `references/performance-physics.md` 的映射表。**这是把表演写对的关键，不要自己发明动作。**

### 阶段 3.5：设计预演（动笔前，不是可选项）

**这一节回答**：动笔前要把演技、调度、镜头、台词、声音想成一条什么因果？**上游**：戏眼与主动作；**下游**：阶段 4 的七段写法与阶段 5 的自检。

把演技、调度、镜头、台词、声音一起过一遍。**这些问题是帮你想，不是考你。** 如果某条默认不适合这场戏，先说清你的理由，再按戏写；说不出理由，就按默认。

**演技**

- 他想要什么？谁挡着？他愿意为此做什么？
- 被碰到/被逼到/被看见时，身体先怎么反应？（局部→惊跳→定向→评估→对抗/顺从）
- 哪个部位先动：眼、眉、下颌、手？收在哪？
- 他的泄露是什么？他用什么遮盖？
- 听的人/旁观的人怎么反应？谁先动、谁不动？

**调度**

- 谁站/坐在哪？谁想靠近、谁想退开、谁不动？
- 谁先动、谁跟着动、谁不动？
- 谁从哪个 P# 走到哪个 P#？经过什么障碍？
- 谁被桌子/椅子/门/人挡住？谁有退路？
- 谁看谁？谁不看谁？谁知道什么？

**镜头：从关系推镜头，不要从景别推**

1. **关系 → 支点**：谁从什么变成什么？观众跟着谁、最后一口画面是什么？在脑子里比较≥2种排法——A 高度（低角王→高角虫）、B 走位（他退→她进→桌成陷阱）、C 物件（杯→礼物袋→椅→杯落地）——选 1 个主设计支点 + 1 个辅助。答不出，回戏核。
2. **支点 → 镜头表**：每镜写高度/角度、景别、前景/遮挡、发生什么、切因。行数由戏决定：对话 2–4；设计版/动作场 5–7；核心是一个瞬间 3–4（但覆盖来向/接触/后果）；POV / 一镜到底例外。**少全景 ≠ 全近景**：用中景 + 人物移动 + 前景/背景交代空间，不是退回平视中近景。漫剧/2.5D/动画风用剪影、负空间、低/高角、前景遮挡，不用风格词代替机位（`camera.md` 二c、二d）。
3. **镜头表 → 默认检查**：单元内相邻两镜默认换两件（景别/轴线/主体/人数/高度角度），其中一件优先高度/角度或轴线侧；全单元至少一个非平视正面（全单元都在眼高若是刻意的，写出理由，可由走位/前景/轴线/景别替代）；叙事场至少一个反应镜，有物件/伤口/关键信息加插入镜，动作场两者都要。镜头多了，**前景/遮挡**是让观众知道"谁在看/什么挡着"的最便宜答案（5 镜以上通常至少 3 镜，纯平面可用框中框/色块替代）；**换焦段**是为了改变观众与人的距离，需要变才换（通常两档：广角 ≤28 / 中焦 35–50 / 长焦 ≥65），不需要就锁定一档、用高度/走位/前景承担变化。**这些是默认，不是配额。**
4. **镜头 → 台词/声音**：哪一镜说话？镜头是否静止、脸可见、够长？这句话是动作、信息还是试探？什么声音证明接触/移动/画外？声音和台词谁先谁后？答不上，回镜头或表演。
5. **每一刀回读**：观众知道更多、站得更近、或更怕一点？都没有就删。

**四个底线（最后回读）：**

- 至少一处**人物位移或刻意的静止**改变关系；
- 至少一个镜头用**中景/近景 + 人物移动或前景/背景**交代空间，而不是全景；
- 至少两镜之间变化的是**权力/信息/立场**，不只是景别；
- 至少两镜的**高度/角度不同**，其中一镜不是平视正面；**如果全单元都在眼高是刻意的**，这条可以由走位/前景/轴线/景别替代，但要写出理由。

不要为了设计而设计；如果全场必须静止，写出压力。镜头表不用写进提示词，也不用给用户看；它只帮你把每一刀想清楚。这些思考不用写出来，它们只决定你写哪一句、排哪一镜、让谁先动。**写长提示词时，多出来的字给动作因果、接触证据、空间交接、声音时序；不要给形容词。** 想清楚后一次写成——落笔时，你已经在脑子里比较过三遍；不要把思考留到写完之后，落笔只有一条提示词。

### 阶段 4：写提示词

按固定七段骨架写，顺序不要变：

```
CHARACTER → POSE AND STAGING → TIMELINE → CAMERA → PHYSIOLOGY PRIORITY
→ LIGHT AND ATMOSPHERE → CONSISTENCY LOCK
```

**TIMELINE 的节拍算法**：节拍数 = ⌈时长 ÷ 1.2⌉，末拍延长到 1.6–1.8 秒。一拍只推一件事，时间码首尾相接、累加等于时长。

现成骨架见 `templates/scene-10s.md`，**单个镜头怎么运动**见 `references/camera-motion.md`，静态镜头参数与视觉论点/高度阶梯见 `references/camera.md`，**镜头之间怎么接**见 `references/shot-continuity.md`。

### 阶段 5：自检与输出

**写前四检**：身份 / 拓扑 / 人数 / 轴线（`spatial-anchoring.md` 2.4）。四条不过，不写提示词。

```bash
node scripts/check_prompt.mjs prompt.txt --duration 10
```

它查十类：段落完整性、时间码空洞/重叠/溢出、节拍数与时长匹配、`[Shot N]` 是否带 `At 00:0X.000`、CAMERA 段仰俯冲突、对白标记与语言标签、人数锁（肢体数量不再检查）、否定式残留、多视图是否加了 `exactly one single figure`、**跨条引用**（`as before` / `previous shot` 这类在跨单元时没有参照物的表述）。

脚本判不了的三项必须人工过：**一拍是否只推一件事 / 生理层是否错开 / 有没有不可拍摄的形容**。设计层再加五问：**主设计支点是否在两个以上镜头兑现 / 镜头表是否列过且相邻两镜换了两件（含高度/角度或轴线侧） / 是否至少一个非平视正面（全平视是否有理由）且三镜不是同骨架 / 动作场是否覆盖五段（默认 5–7，瞬间 3–4 也可）且微距只做证据 / 少全景与人物位移是否做到**。**长度：超 7000 字符才压缩；压缩只删重复、同义、无职务，不删因果/证据/交接/声音。** 对白专项再加四项：**话轮不是排队 / 听者在台词中反应 / 失语落在最难词且发生在身体 / 三股力量并存且外显只留一个**（`dialogue-performance.md`）。

## 四、剧集模式：七步（顺序不能变）

**这一节回答**：一集怎么从资产到逐单元？**上游**：单条链路；**下游**：每单元五步 + 2.5 设计预演。

用户要做一集多单元短剧时，**不要从读图开始**。完整版见 `references/series-workflow.md`。

> **前提（整套流程的地基）：H3 每次生成都是无状态的。** 它不记得上一镜谁站在哪、刀在谁手上、刚才说过什么。它只有两样输入：**这一次上传的图 + 这一串文字**。
>
> 两条直接后果：
> ① 参考图不是加分项，**它是跨单元记忆本身**——"额外锚定图"这个叫法容易让人误会成"顺便参考一下画风"。
> ② 文字必须自包含：`still` / `same` / `as before` 在跨条时是空词（没有参照物），要换成对当前状态的直接描述；每一镜都要重新陈述画面里所有关键物件（手上的刀、盖到胸口的被子、关着的门）。

```
1 项目规格      画幅/时长/风格锁原文/调色/音频策略/交付形态/空间账本（N/P/K/c/轴线/覆盖）      （一次定，全集复用）
2 资产需求表    每张图只准提供什么 + 必须排除什么                （见 asset-production.md）
3 资产生成提示词 每张五段，第一句是同一段风格锁                   （一次给全）
4 出图并核对    差异对照表：假设 vs 实际                        （不许省）
5 反向修正      改身份锁 + 用资产里已有的特征改剧本钩子
6 单元编排      情绪曲线 + 钩子表 + 视角轮换表
7 逐单元写提示词 走 shot-intake.md：状态卡/账本 → 读图七项 → 定戏眼 → 2.5 设计预演 → 定视角 → 组装；第0步后先过四检
```

### 五个决定成败的点

**其一，资产必须先行。** 先写提示词再去凑图，会撞两个死结：你写的身份特征图上不存在；你写的空间关系图上不成立。先定资产，提示词就是"描述已有之物"，命中率高一整个量级。

**其二，身份卡永远是立姿，不是剧情姿势。** 用户说"她侧躺在床上的样子"要作为身份卡时，要主动纠正：**姿势交给提示词的 `POSE AND STAGING`，身份卡只负责脸和衣服**。锚点图带姿势，后面每一集都要花力气压它，而且压不干净。

**其三，出图之后必须核对，且差异要反向写回剧本。** 写了"虎口的疤"而实际资产没有，就不能继续用这个疤做伏笔——换成资产里真实存在的特征（比如颈侧的痣）。用不存在的特征做钩子，第 5 集无解。核对表与案例见 `references/asset-production.md`。

**其四，成片锚点只留最新一张。** 两份成片记录的是两个不同时刻的空间关系，一起传会让模型取中间值。每换一个单元，上一张成片退场。规则见 `references/slot-economy.md`。

**其五，空间账本先行。** 多单元、3 人以上、有固定席位或正反打时，先从场景图建账本（N/P/K/c/轴线/覆盖），再写地标/调度图/五锁；否则每单元都在重新理解场景，第三个单元开始漂。规则见 `references/spatial-anchoring.md`。

### 每次换单元前必须回答的五个问题

```text
1 上一镜结束时，两个人在房间的哪两个位置？（用"床头那侧 / 门那侧"，不用左右）
2 上一镜结束时，主光从哪边来？辅光在哪？
3 上一镜结束时，谁手上有什么东西？放在哪？
4 这一镜的第一个动作，从上面那个状态开始，还是从它之后？
5 这一镜换视角吗？换成什么？带来六种新信息里的哪一种？
```

答不上来，不许动笔。

**答完五问，再做四检**：身份 / 拓扑 / 人数 / 轴线（`spatial-anchoring.md` 2.4）。五问确认"接得上"，四检确认"没写乱"。

### 接续模式：三选一，混不了

H3 里**参考图模式与首尾帧模式互斥**。

| 模式 | 传什么 | 用在哪 |
|---|---|---|
| A 参考图 | 场景空镜 + 角色锚点 2–3 张 | 机位跳变、换视角 |
| B 尾帧 | 上一镜成片最后一帧作首帧（**不能再带参考图**） | 同机位、动作连续 |
| C 参考图 + 成片锚点 | 场景 + 锚点 + 上一镜成片 | 剧集的主力做法 |

**判断法：动作连续走 B，机位跳变走 A/C。**

尾帧截取：截最后一帧、**往前退 0.2–0.3 秒**（成片比请求多 0.5–0.6 秒）、存 PNG、不缩放。

## 五、硬规则

**这一节回答**：H3 的能力边界是什么？**上游**：总纲二；**下游**：所有镜头/表演/台词写法。

**失败模式不是另一套规则，是链的断点。** 身份断、空间断、表演断、镜头断、台词断、声音断。先回上游，不要在下游硬修。

### 先记这四条：H3 的能力边界（优先级高于下面所有通则）

这四条不是风格偏好，是模型特性决定的。前三条违反了会让成片"看起来廉价"，第四条违反了会让画面"看起来假"。

0. **信任它的空间理解，不要过度设防。** H3 是旗舰级视频模型：多角色同时反应、身体重心转移、视线锁定、复杂的双人互动，它都处理得了，**不会凭空多出一条胳膊或者把肢体融化**。所以一致性锁只写"人数 + 状态 + 惯性 + 身份标志物"，**不写 `two arms` / `ten fingers` / `two legs`**。
   > 这条排在最前面，因为它是一种心态。担心它崩，就会在锁里堆一堆"不要变形"，而这些词占掉的正是本该用来描述动作和空间的注意力预算。**写得越具体它越准，防得越多它越保守**——保守的成片就是"一个人在动，其他人在等指令"，比肢体崩坏更假。
   >
   > 唯一的例外：某个项目**实测**在这一处崩过，才针对性写一次，而且只写崩的那一处。

1. **相邻单元绝不同构图。** 单元是独立生成的，同一构图的两次生成必然有微差（脸的角度、光的强度、布料褶皱）。单看每段都没问题，**但两段剪在一起观众会看到画面"跳"了一下**——这是短剧里最容易被察觉的廉价感。规则：**五根骨架（景别档 / 轴线侧 / 主体位置 / 入画人数 / 高度角度）至少换两件，其中一件必须是高度/角度或轴线侧**；判据是"两张截图并排，闭眼都能看出不一样"。
   > 这也是成片锚点必须写 `copy zero of its framing and zero of its camera position` 的真正原因——不写，模型会连机位一起抄走，于是这一单元变成上一单元的翻拍，正好撞上这条。

2. **景别跟着"要不要读脸"走，不是跟着配额走。** H3 的脸部可读性随景别衰减：大特写/特写最锐利 → 近景锐利 → 中近景稳 → **中景变软但仍然可读** → 全景/远景只剩轮廓。
   - 判据一句话：**这一镜需要观众读到脸上的信息吗？** 需要（台词、眼神变化、微表情、情绪转折）→ **中近景以内**；不需要（氛围、位置、气势）→ 中景到全景都可以，**而且全景往往更有力量**
   - **全景不是禁区。** 剪影、背影、逆光里的轮廓，这些镜头不存在"糊脸"——因为本来就不需要读脸。巨大月轮下的人影、门缝里的全身、雨中的走远，远景正是最优解
   - 三条仍要守：**主角第一次出场在近景以内**（观众得先认识这张脸）；**情绪转折点不用全景**；**长台词不放中景以外**（口型误差会被放大）

3. **场景图是三维地图，不是取景框。** 它提供房间结构（墙、门、窗、家具、光从哪来），**机位由这一单元自己定，可以放在房间任何位置**。声明里写 `the camera position for this shot comes entirely from the CAMERA section below`，再用一句话把机位钉在房间的具体位置。不写，模型会退回参考图的视角，于是所有单元都是同一个角度。**但它是拍摄弧，不是 360°。** 未见墙面不假设；反打补一张反方向环境卡，或让背景保持近景虚化。**没有俯视图时，按 `spatial-anchoring.md` 3.1b 从场景图读节点表；不要要求用户补俯视图。** **场景图不是构图参考：第一镜不得复用场景图的机位，相邻镜头优先换高度/角度或轴线侧。**

### 再记四条：空间与对白（2026 升级）

1. **一个空间事实只准有一个主人。** 世界拓扑归 L1 账本（`World:`），身份归 c#（`subject_definitions` / 槽位声明），屏幕侧归本镜投影；同一事实写两遍不是加强，是给模型两个版本。屏幕侧只在本镜出现一次。**状态从成片，拓扑从账本。**
2. **正反打的肩侧 = 视线侧。** 焦点人物看向前景肩所在的那一侧；A/B 相反；手性开场定一次，整场不改；换侧必须靠切。
3. **人数分三级。** 房间总人数（账本）/ 帧内人数（本镜）/ 进出事件（时间码）；画外的人不传身份卡，出画不等于离场。多人场景优先机位移交（一镜推/弧线，不跨轴，台词前停稳）。
4. **对白不是排队。** 抢话、叠话、插不进、沉默、失败启动；听者在台词进行中反应。话轮与失语见 `references/dialogue-performance.md`。

### 再记四条：设计（2026 升级）

1. **少全景。** 能用中景 + 人物移动 + 前景/背景关系交代空间，就不用全景；全景只给三种情况：空间规模/孤立/命运、人物变成图案、开场/收场需要社会关系图。人脸在远景里最容易崩。**少全景 ≠ 全近景**：退回一串平视中近景，是另一种 coverage；用中景 + 前景 + 位移建立空间。
2. **人物要移动。** 至少一处人物位移或刻意的静止改变关系；镜头可以不动，让人物在画框里移动。没有走位的镜头，要么是刻意的静止（僵住/权力/等待/观察），要么只是 coverage；写出它为什么不动。
3. **每一刀要切因，每一镜要新信息。** 每刀至少改变权力/知识/立场/距离/尺度/节奏之一；两镜做同一件事，删一个。切碎不是同高度多切几刀，是切成更多权力状态。
4. **镜头设计不是景别三件套。** 写 CAMERA 前先列镜头表（高度/角度、景别、前景、切因；思考工具，不交付）；**单元内**相邻两镜默认换两件（含高度/角度或轴线侧）；全单元至少一个非平视正面（全单元都在眼高若是刻意的，写出理由）；动作场默认 5–7 镜，核心是一个瞬间时 3–4 镜也可以，但必须覆盖"来向/接触/后果"，不能三镜只换景别；每一刀切因不设例外。三镜说清理由也可以是好设计，七镜只换景别也只是碎 coverage。漫剧/2.5D/动画风也一样，风格词不是机位。**这条讲单元内；相邻单元另按本节第 1 条“相邻单元绝不同构图”的硬规则。** 详见 `camera.md` 二c、二d。

### 再记这十条通则（按出错频率排序，前五条违反了提示词基本报废）

1. **每个 `[Shot N]`（N≥2）必须带 `At 00:0X.000, the camera cuts to ...`**——紧跟在标签后，或写在标签前，两种都接受。只写标签不写时间码，切点会晚 1–2 秒。
2. **时间码首尾相接，累加等于时长。** 有洞 → 空白帧；重叠 → 动作打架。
3. **台词只放在脸可见的镜头，且该窗口镜头必须静止、焦点锁死。** 窗口里不要同时安排动作——让他停手说话，说完再动。
4. **一致性锁必须在最后一段，写人数 + 状态 + 惯性 + 身份标志物。** `keep the pose` 无效；`her weight stays on her front foot, her spine tilted two degrees forward` 有效。**不写 `two arms` / `ten fingers` / `two legs`**——H3 不会融化肢体，这些是廉价保险，占的是描述动作的预算（详见上面第 0 条）。
5. **H3 没有负向分支。** `no` / `不要` / `禁止` 不会压制概念，可能被正向采样。全部改成可见的确定状态。用 `zero people` 而不是 `no people`。
6. **`non_diegetic_music` 必须写。** 不想配乐也要写 `N/A`，否则模型自己补一段，且音量不小（实测差 25 dB）。
7. **一拍只推一件事。** "坐下 + 脸红 + 抓床单"是三拍，写成一拍三样都只做一半。
8. **镜头运动 ≤ 2 个，且两个必须物理连续**（推+仰可以，推+绕+摇不行）。CAMERA 段不许出现两套矛盾的机位（仰拍 + 俯拍同时写，画面会跳四个机位）。
9. **跨风格必须三件套**：槽位排除旧渲染 + 镜头首句钉死目标风格 + 细节处复述风格。缺一个就会"动漫脸配真人毛孔"。
10. **画面内可见文字加英文双引号。** 不加引号的招牌字几乎全部变乱码。

| "换个人" | 只换 CHARACTER 段和槽位声明 |
| "加台词" | 找 7.2–10s 窗口，镜头静止，焦点锁脸，超过 12 字拆两段中间停 0.6–0.8s |

| "悲伤没层次 / 说不出口 / 只会五官齐飞" | 三股力量 LEAK / CONTROL / CARE 同时存在；失败落在最难面对的词上、发生在身体里（`dialogue-performance.md` 六、七） |

## 八、输出格式

**这一节回答**：交付长什么样？**上游**：全部；**下游**：用户。

默认按这个结构交付，不要写成方案分析：

1. **一句话戏眼**——这一单元最值钱的那一秒是什么（"最后两秒她被锁在门口，笑垮在眼睛里"）。用户靠这一句判断方向对不对，**没有它，后面的提示词他没法评估**
2. **一句关键决策**——主设计支点 + 为什么这样拍（"走位版：他退到餐桌、她跟进，桌子变成陷阱"）
3. **素材分工表**（发图时）：编号 / 职责 / 排除
4. **节拍表**——五列：`| 秒 | 镜 | 高度/角度 | 景别/前景 | 发生什么（这一拍改变了什么）|`。高度/角度必须具体（低角 0.9m / 高角 2.2m / 平视），不能只写景别；每拍后面用括号补一句改变了权力/信息/立场/距离中的哪一项。这是给用户看的执行方案，让他能在生成前就判断节奏和镜头设计对不对
5. **提示词**：一个英文代码块，单段可复制，内部七段全大写标签
6. **参数建议**：duration / resolution / ratio 三行
7. **崩点表**：3 条左右，只写这条特有的，每条给"症状 → 修法"
8. **一句"如果不对，先改这三处"**——具体到句子，不要泛泛而谈（"如果她的笑收得太快，把 `holds it without letting it fade` 和 `holding unchanged through 10.00s` 一起加"）

**剧集模式的交付差异**：

- 第 1 步交付资产清单 + 每张图的生成提示词，**一次给全**
- 第 4 步之后，每轮只交一条视频提示词 + 上传顺序 + 3 条崩点
- **不写文件**，直接在对话里给代码块（用户要复制的是提示词，不是文档）；除非用户明确要求归档
- 每轮开头用一两句说清"这一镜的戏眼在哪"，这是用户判断方向对不对的唯一依据

语言：**提示词正文英文，其余中文。**

### 四条写作纪律（这一轮踩出来的）

**其一，一条规则只写一处，其他文件只引用。** 同一件事在 `SKILL.md` 和 `references/` 各写一份，改的时候必然漏一处，然后两处互相矛盾——这种矛盾自己通读十遍也发现不了，因为两处看着都对。写新规则时先问：这条的"唯一事实源"放在哪？其余地方只留顺序或结论。

**其二，改完必须用"没有上下文的 agent"盲测，它能读对才算写清。** 做法：起一个不读本对话的 subagent，只给它文件路径和一段用户口语（不给任何背景），要求它回答"这几张图分别该怎么派活""该传几张""这是什么衔接类型"。规则默会写在脑子里时，写出来的句子只有知道答案的人才读得懂；盲测是唯一能暴露这件事的办法。

这一轮实测：概念改到第三版时分类才唯一，四轮盲测一共挑出九处卡点——包括"用像不像成片来判断是不是成片"这种只有照做才会撞上的逻辑错。

**其三，先写链，再写规则。** 每一节开头先回答"这一节解决链上哪一层、上游是什么、下游交给谁"，再写规则；读者先拿到位置，规则才不是孤立清单。新增一节时，先问它插在哪条边。

**其四，规则写成"默认 + 例外 + 原因"。** 不写绝对命令；模型需要知道为什么，才能在戏不适用时做出正确判断。例："动作场默认 5–7 镜；核心是一个瞬间时 3–4 镜也可以，但必须覆盖来向/接触/后果"，而不是"动作场必须 5 镜"。

- **剧集流程的七步顺序是硬约束**。任何"加快"的冲动都要问一遍：跳过的是哪一步，代价是什么（见 `series-workflow.md` 第六节）。
