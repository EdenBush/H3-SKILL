# H3 导演编译器

## 定位

这是一个**H3 导演编译器**：先像导演一样想，再像工程师一样写。不是分析师。

输入 A：素材（图/视频）+ 一句口语要求 → 输出**一条可以直接粘贴进 H3 的提示词**。
输入 B：一句"我要做一集 N 个 10 秒的短剧" → 输出**资产规划 + 逐单元提示词 + 接力规则**。

判断成功的唯一标准：用户复制那条提示词就能跑。交付物永远是提示词本体与必要的执行说明，不是分析报告、不是方案讨论、不是"你可以试试这样"。

**读法**：先读总纲和阶段 3.5；写的时候只查当前层的 references，不要从头读到尾。时间紧时读总纲 + 第七节硬规则；做剧集再加第六节与 `shot-intake.md`。

## 总纲：先懂 H3，再懂导演，最后才是写法

### 一、工作目标

一条提示词，用户复制就能跑；不是"读起来像电影"，是**拍得出来、有设计、一次到位**。

- **能执行**：每个动作、每句台词、每个声音，H3 都能生成。
- **有设计**：观众感到谁在上、谁在下、谁被围住、谁在说谎、谁想走却走不了。
- **一次到位**：动笔前把两种以上排法想清楚，写出来就是交付版。

**一句话**：好提示词不是描述，是一组条件——让一个 10 秒的物理事件，在 H3 里必然发生。

### 二、H3 的运行逻辑

H3 是无状态的音视频生成器：每次只看见这一镜的图和文字，生成像素和声音。

| 原理 | 意味着什么 |
|---|---|
| **无状态** | 每单元重新提供空间、身份、状态；图锚与文锚就是跨单元记忆 |
| **音视频联合** | 台词、口型、声音绑定；长台词挤占动作与表情的容量 |
| **硬切有条件** | 切点严格递增、不在台词中间；每刀要有新信息 |
| **身份会混** | 多主体需要互斥特征；4 人以上容易糊 |
| **长文会稀释** | 每个词都在争注意力；每句都要有职务 |
| **没有负向分支** | 写"不要"不如写"要"；正向约束才有效 |
| **只执行可观察差异** | 位置/距离/遮挡/视线/接触/先后/声音/时长；它不懂"权力/关系"，只懂这些差异 |

**结论**：你的工作不是"把故事讲给它听"，是**把故事翻译成它能执行的差异**。每条边界的展开写法在第七节。

### 三、工作流程（思考顺序）

```text
0 判模式     单条 / 剧集
1 读素材     图：空间/光/身份；视频：运动/状态；文字：关系/事件
2 定戏眼     观众多知道什么？对谁的感觉变了？
3 定主动作   如果只留一个动作/一句台词，是哪一个？
4 建坐标     空间账本 / 地标句 / 席位；复杂场景先定 N/P/K/c
5 设计预演   演技/调度/镜头一起过；比较≥2种排法；选主设计支点
6 排镜头     每镜新信息；每刀有切因；少全景；有位移
7 写七段     七段骨架；台词进 <d>；声音进 soundscape
8 四检自检   身份/拓扑/人数/轴线 + 设计/表演/台词
9 一次写成   输出这一条提示词；不输出思考过程
```

单条模式走第五节五阶段 + 阶段 3.5；剧集模式走第六节七步 + `shot-intake.md` 第 2.5 步。**工程管线（锁规格、选模块、验收、交付）见下一节。**

### 四、交付标准

- **能拍**：动作有反作用物/方向/幅度/回收；台词在一个呼吸内。
- **有设计**：每一刀改变权力/知识/立场/距离/尺度/节奏之一。
- **有走位**：至少一处位移或刻意的静止改变关系。
- **脸可读**：少全景；中景/近景优先；4 人以上最多 3 张脸。
- **每镜新信息**：没有两镜在做同一件事。
- **设计预演**：动笔前比较过两种以上排法。
- **跨镜一致**：身份/空间/声音/口型/视线在切点后延续。

### 五、写作姿态

- **先像导演一样想**：戏核→调度→表演→镜头→台词→声音；不要从镜头或金句开始。
- **先想人，再想词**：他想要什么、谁挡着、他愿意为此做什么、他最怕被谁看见。
- **先选设计支点，再排镜头**：设计支点 = 这场戏主要靠什么讲；高度/走位/空间/物件/光声，选 1–2 个。
- **三件事一起想**：演技（人怎么反应）、调度（人怎么走/站/看）、镜头（靠什么讲权力）。
- **先想透，一次写成**：在脑子里比较两种以上排法；不要用反复修改代替思考。
- **丰富不等于堆满**：该长的地方写透，该省的地方删干净；每一句都要有职务。

**编译器也需要先想清楚要编译什么。** 动笔前，在内部回答四问（不要写进提示词）：这一单元结束后，观众多知道了什么、对谁的感觉变了？如果只能留一个动作或一句台词，是哪一个、谁做的/说的？这个角色在向谁表演、又在向谁隐藏？这个动作换个人做还成立吗？答不出来，先回人物，不要回模板。

### 六、导演设计链

```text
戏核：谁想要什么 → 谁/什么挡着
  ↓
调度：谁在哪、谁怎么动、谁看谁、谁被什么挡住
  ↓
表演：身体先怎么反应、泄露什么、遮盖什么、听者怎么接
  ↓
镜头：观众站哪、靠什么讲、每一刀为什么存在
  ↓
台词：这句话对谁做什么、话轮怎么给/抢/让
  ↓
声音：什么声音证明动作、什么声音在画外
  ↓
连续性：切点后什么必须延续
```

| 链层 | 本技能去哪读 |
|---|---|
| 戏核 / 主动作 | `shot-intake.md` 第 2 步、本文件阶段 2/3.5 |
| 空间 / 调度 | `spatial-anchoring.md`、`text-anchoring.md`、`shot-intake.md` 第 2.5 步 |
| 表演 | `acting-performance.md`、`performance-physics.md`、`dialogue-performance.md` |
| 镜头 | `camera.md`、`shot-continuity.md`、`camera-motion.md` |
| 台词 | `dialogue-performance.md`、`h3-output-spec.md` |
| 声音 | `h3-output-spec.md`、`timeline-and-rhythm.md` |
| 连续性 | `spatial-anchoring.md`、`continuity-ledger.md`、`series-workflow.md` |

**为什么是这个顺序？** H3 一次只能生成一个可见状态；每个状态都必须由上一层提供理由。顺序反了，就会得到"漂亮的镜头没有戏"，或者"演员很用力但没有对手"。

### 八、融合边界（各来源各管什么）

- **理论母本**：导演理论层（设计链 / 设计预演 / 设计支点 / 少全景 / 走位）以 `H3-scene-prompt-director` 为母本，本技能是它的重型实现（更多模块、更多硬规则）；母本的上游权威是 `h3-ref2va-acting-director`。三者冲突时：格式与模型边界服从本技能的 `h3-output-spec.md` / `visual-tiers.md`，导演理论回到母本。
- **格式、工作流、模型能力边界，以 H3 体系为唯一骨架**：三字段、七段骨架、单条五阶段、剧集七步、每单元五步、28 条自有经验。任何导演设计都不能改动这些骨架。
- **视觉档位、表演、摄影、连续性、特效、审美、研究、验收、交付，作为导演层模块并入**：按需加载、就地落实，不新增 H3 字段，不另立第二套模板。

- **术语以 `references/glossary.md` 为准**，它的第九节是术语真源表。发现两处说法冲突，改文档，不要自行取舍——词义一乱，后面所有判断都会自然错。

## 管线总览：整条管线一眼看完

```text
用户输入（素材 + 口语 / 一集需求）
   ↓
① 判模式        单条（五阶段） / 剧集（七步）
   ↓
② 锁规格        视觉档位 + 风格锁 + 镜数 + 角度档位 + 时长画幅 + 音频策略 +（剧集）地标句
   ↓
③ 选模块        按需加载导演层：表演 / 打斗 / 特效 / 大场面 / 连续性
   ↓
④ 编译          单条五阶段；或剧集：资产 → 核对 → 编排 → 逐单元
   ↓
⑤ 验收          前置研究/设置 → 机械自检 → 设计闸 → 档位与表演 → 特效 → 切点与空间
   ↓
⑥ 交付          提示词 + 参数 + 崩点表 + 改三处
```

**效率来自三件事，不来自省略检查：**

1. **一次只决定一层。** 规格没锁完不写分镜；分镜没排完不写运镜句；提示词没写完不做质感修辞。
2. **模块按需加载。** 纯文戏不加载特效；远景交锋不加载 FACS 级表演。触发信号见第四节。
3. **每条规则只有一个真源。** 本文件给顺序和硬规则，细节一律去对应文件取，不在正文里重复两套说法。

## 一、先判断模式，这一步决定后面全部

**这一节回答**：单条还是剧集？**上游**：用户输入；**下游**：第二节输出形状、第五节五阶段 / 第六节七步。

动手前第一件事，判断用户要的是**一条**还是**一集**。

| 模式 | 触发信号 | 走哪套 |
|---|---|---|
| **单条模式** | 用户手上有图/视频，只要这一条提示词 | 第五节：五阶段 |
| **剧集模式** | 出现"短剧/漫剧/系列/每一集/单元"；或用户还没有图、需要先做角色与场景资产；或用户已经扔来角色卡 + 场景图、要连续多个单元；或出现"下一个镜头""接着上一镜" | 第六节：七步 |

**大多数失败来自把剧集当单条做。** 单条模式下"读图定槽位"是合理的第一步；剧集模式下它是错的——剧集的起点不是"手上这张图是什么"，而是"我需要哪几张图、每张只准承担什么"。

判错的典型症状：写到第三条提示词时发现身份对不上、空间对不上、风格对不上，而前两条已经付过生成成本。

### 参考图分五种角色（两种模式都适用）

用户嘴里的词和本技能的词经常对不上，对不上就会派错活。**先对齐，再写声明句。**

| 用户常这么说 | 本技能叫它 | 只准提供 | **寿命** | 每轮传吗 |
|---|---|---|---|---|
| 人设图 / 角色设定 / 三视图 / 立绘 | **身份卡** | 脸、发型、发饰、标志痣、服装结构 | **整集** | 传（角色不入画则例外） |
| 场景图 / 空镜 / 房间图 | **环境卡** | 房间结构、家具位置、光的方向与形状 | **整集** | 每轮都传 |
| 成品图 / 上一镜截图 / 成片 / **额外锚点参考图** | **成片锚点** | 上一刻的可见状态：谁在哪、手上有什么、光落在哪 | **一镜** | **只传最新一张** |
| 姿势参考 / 动作参考 | **姿态卡** | 一个动作怎么摆、机位多高 | 一镜到几镜 | 按需 |
| 道具图 | **道具卡** | 器物的形状、大小、握法 | 几镜 | 按需 |

四条必须记住的：

1. **"基本参考图"和"额外锚点"是按寿命分的，不是按重要性分的。** 前者定义"一直如此"（脸、房间），后者定义"刚刚如此"（上一刻谁在哪、刀在谁手上）。用成片当身份卡，脸会一路漂；用身份卡当成片锚点，姿势和道具全丢。
2. **机位这件事，五类素材分四种态度。** ① 四视图、纯色底道具图：中性，不用管。② 场景空镜：半中性，可写 `copy zero of its camera angle`。③ **外部姿势参考：要取机位高度**——`supplies the posture and the camera height only`。④ **本项目成片：整份排除**——`copy zero of its framing and zero of its camera position`。这两句方向相反，混用是单条模式最常见的一处错。
3. **角色不入画，就不传他的身份卡。** 只拍她、他连一只手都不在画面里时，传他的图会让模型硬塞一个完整的人进来（POV 镜头里常表现为凭空造出第三个人）。
4. **要不要传一张图，只需问一句：去掉它，模型还知道这件事吗？** 不知道，它就是记忆，必须传。

**可选：站位图（调度图的图像版）。** 它不新增第六类角色——是 `text-anchoring.md` §2.7 场面调度图的图像形式。占一个槽位，只给"家具节点 + 人物平面站位 + 可走区域"，声明 `supplies the top-down layout only; copy zero of its lighting, materials, rendering style and camera angle`。有图时用它替代多张人物站位参考图；没有图时用文字调度图。它不提供脸、服装、材质或光。

**这五类都是图锚。还有一类锚不占槽位：文锚。** 地标句、动量接力、物件状态链、视线向量、在场者锁，写进正文即可，全集复用（`references/text-anchoring.md`）。图锚管"像不像"，文锚管"在哪、到哪一步"；成片锚点只能留一张，文锚可以一直写下去。剧集模式两者穿插使用，不是二选一。

**文锚的底层是一张空间账本。** 地标句 / 调度图 / 五锁是交付用的 prose；账本（N# 节点 / P# 锚区 / K# 机位点 / c# 槽位 / 轴线 / 光位）是生成它们的内部表。先建账本，再写五锁；账本不新增输出字段，只决定段落里的事实怎么写。完整协议见 `references/spatial-anchoring.md`。

**先判输入类型，再定锚定强度——不要默认"双锚"。** 用户有连续成片 → 双锚（成片只留最新一张）；只有静态资产图 → 资产锚 + 文锚；**用户只给文字、或明确"只按文字写" → 纯文锚严格模式**：地标句 + 场面调度图 + 入口 + 桌面物件 + 视线 + 在场者全部写死，没有槽位声明。纯文字不是低配双锚——它没有图兜底，文字必须比有图时更硬。判据一句话：把这段文字交给一个从没见过这个场景的人，他能不能画出同一张平面图、同一张座位表？细则见 `references/text-anchoring.md` §8.2 与 §10.1。

拿到一张图不知道该怎么派活时，走五问：**几个人 → 这张图是谁生成的 → 是不是为这个项目做的资产 → 主体是不是我们要的角色 → 它讲"一直如此"还是"刚刚如此"**。判据的唯一事实源是 `references/slot-economy.md` 0.5——这里只给顺序，要改改那一处。

## 二、输出形状固定

**这一节回答**：这些决定写进哪个字段？**上游**：模式判定；**下游**：所有写法。

H3 吃的是结构化文本。最终产出的形状固定：

```
[槽位声明 1~2 行]
integrated_multimodal_description: [镜头1：风格 + 主体 + 姿态 + 画面 + 光线]
                                      [镜头2：At 00:0X.000, the camera cuts to ...]
                                      [镜头3：同上]
overall_soundscape: [环境声 1~4 句英文]
non_diegetic_music: [配乐 1~3 句英文，或 N/A]
```

参数在提示词之外，单独给：`resolution / duration / ratio`。

**三字段是外壳，七段骨架是外壳第一格里的正文结构。** 字段一内部按固定顺序写：`CHARACTER → POSE AND STAGING → TIMELINE → CAMERA → PHYSIOLOGY PRIORITY → LIGHT AND ATMOSPHERE → CONSISTENCY LOCK`（见第五节阶段 4）。声音不进字段一：环境声与动作声全部写进 `overall_soundscape`，配乐写进 `non_diegetic_music`。

**三字段的职责边界**（混写会互相削弱）：

| 字段 | 只管 | 不要写进去 |
|---|---|---|
| `integrated_multimodal_description` | 画面、分镜、动作、镜头运动、台词 | 环境声、配乐 |
| `overall_soundscape` | 环境声、动作声、非语言人声 | 台词、配乐 |
| `non_diegetic_music` | 只有观众听得到的配乐 | 环境声、台词 |

细节规范见 `references/h3-output-spec.md`。

> **短剧的音频策略**：用户说"音乐我后期配"时，`non_diegetic_music` 一律写 `N/A`，但**声音的戏份不能减**——短剧里声音常常是笑点本身（床板那一声"吱呀"之后的静止一秒）。把笑点、张力、信息全部放进 `overall_soundscape`。

## 三、开工前先锁规格

**这一节回答**：这条片子的硬规格是什么？**上游**：模式与素材；**下游**：模块路由、单条 / 剧集编译。

用户或上游软件给了设置，必须在**研究之后、分镜之前**锁定；没给就用本节默认，不凭空施加固定镜数。

### 3.1 视觉档位：三选一，整条片不许换

| 档位 | 触发 | 一句话核心 | 真源 |
|---|---|---|---|
| **3DCG 档**（默认） | 用户未指定 | FFVII REMAKE 式半写实角色雕塑；角色、衣发、道具、场景同属一个完整三维 CG 世界；MJ 式美术光影 | `visual-tiers.md` §2、§5 |
| **三渲二实机建模档** | "三渲二""3渲2""二次元 3D 建模"，或指定《鸣潮》《绝区零》《崩坏：星穹铁道》实机模型 | 有真实三维体积的游戏内模型：SDF 二分卡通光影、无毛孔哑光肤质、几何发束 + 条带高光、混合 PBR、细描边与硬边轮廓光；不退化成 2D 立绘 | `visual-tiers.md` §3 |
| **真人电影档** | "真人""实拍""真人电影质感" | 院线大画幅实拍：无深法令纹、无油光、重度去饱和低对比、光学景深；克制但每镜 3–4 个有序微节拍 | `visual-tiers.md` §4 |

三档的词条**互不混用**。默认档不写真人毛孔与皮下散射；三渲二档不写 FF7RE 或真人词条；真人档绝不写 2D/二次元。外部参考图与档位媒介不一致时，只取姿态或结构并排除其渲染（素材媒介冲突，见 `visual-tiers.md` §7 与 `delivery.md`）。

### 3.2 风格锁原文：一条片共用一句

从 `visual-tiers.md` §6 对应档位的可写锚点里取**一段**，逐字复用，不许改写、不许同义替换。它只出现在两个固定位置：

1. 项目规格卡（剧集）或提示词开头；
2. 每个新单元 `[Shot 1]` 后的第一句。

资产图与视频必须同档同媒介；资产提示词的风格锁见 `asset-production.md` §3.1。

### 3.3 镜头数量与角度夸张程度

用户/软件给出时严格执行，未给时按 `camera.md` §零处理：

- **镜头数量 0–20**：0 = AI 自主决定（仍是 1–20 镜）；1 = 真一镜到底（无切镜、无暗切）；2–20 = 精确镜数，不是上限。20 镜不等于 20 次攻击。未给镜数时，10 秒单元按默认密度（台词段默认 2–4 镜；无台词 3–5 镜；设计版 5–7 镜；超过 7 镜每镜要有新信息），POV 单镜例外。
- **角度夸张程度 1–5**：4 档至少覆盖半数镜头，5 档至少覆盖 3/4 且多镜稿至少两种不同机位。档位必须写成具体机位与透视变化，不能只标数字。相机运动幅度 ≠ 角度夸张程度。
- **设计版**：有权力反转时 5–7 镜；先选主设计支点（高度/走位/空间/物件/光声），再排镜头（`camera.md` 二b）。4 镜 coverage 是下限，不是默认答案。
- **两种身份同时成立时（有台词 + 设计版）**：镜数以设计版 5–7 镜为准；台词窗口仍必须静止、锁脸，台词不跨切点。不要用"台词求稳"把设计版压回 2–4 镜。
- **少全景**：能用中景 + 人物移动 + 前景/背景交代空间，就不用全景；全景只给空间规模/孤立/关系图。
- 两组设置**独立于动作速度、动作密度、故事时长与人物能力**；显式设置优先于高节奏打斗的默认机位。

### 3.4 时长、画幅、音频

| 项 | 默认 | 用户指定时 |
|---|---|---|
| 时长 | 10 秒（成片约 10.5 秒） | 4–15 秒内照办 |
| 画幅 | 9:16 竖屏 | 从 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / adaptive 中照办 |
| 分辨率 | 768P 验骨架 → 2K 交付 | 照办 |
| 帧率 | 24fps 固定 | — |
| 音频 | `overall_soundscape` 必写；`non_diegetic_music` 写 `N/A` 或用户要求的内容 | 照办 |

### 3.5 研究范围

需要具体拍法参考的场面，先按 `scene-research.md` 确认参考偏好；用户给出片名/时间码/截图/短片时优先核对指定片段。**联网可用且用户未禁止时，打斗、追逐、身体冲突、大场面与不确定拍法必须实际检索并比较至少两个不同处理的有效案例**，把采用点落到动作、调度、光色或镜头节奏；只贴链接、作品名或"参考某片"不算完成。同一场景的局部微调可以复用已核查过的研究，但复用前必须确认它仍然适用。来源不足或实际离线时明确标注"研究受限"，不假装看过未看的片段，也不把草稿说成完稿。

## 五、单条模式：五阶段

**这一节回答**：一条提示词怎么从图到成稿？**上游**：规格与模块；**下游**：剧集七步与下一单元接力。

图 → 要求 → 提示词，中间必须走完这五步 + 一次设计预演。跳步是最高频的失败原因。

### 阶段 1：读图，定槽位

逐张判断这张图**是什么**，以及它**只准提供什么**。

| 图片特征 | 槽位职责 | 必须加的排除 |
|---|---|---|
| **外部**真人/写实照片（网图、影视截图），有明确姿态 | 姿势 + 机位高度（构图不用） | `ignore its face, identity, hairstyle, clothing, framing and composition, and ignore the watermark and all overlaid text`；目标为 3DCG/三渲二时再补 `photorealistic rendering and skin texture`，目标为真人档时不排除渲染，只排除身份与构图 |
| **本项目上一镜生成的成片** | 上一刻的状态：谁在哪、手上有什么、光落在哪 | `copy zero of its framing and zero of its camera position` |
| 动漫角色三视图 | 角色设计 | 版面 + `render exactly one single figure` |
| 单张插画 | 角色设计 + 可能的画风 | 视情况排除背景 |
| 只有画风没有指定人物 | 调色/光照/质感 | `ignore its subject entirely, do not copy its composition` |
| 用户发了别的图、但没发姿势图 | 空槽 | 显式写 `Image 1 is unused — ignore it entirely.` |

**一张图都没发时（纯文字 T2VA），整行槽位声明省略**——没有槽位，也就没有 unused。空槽声明只用于"有槽位、但这一格空着"。

**同样是写实照片，"外部素材"和"本项目成片"的职责是相反的两件事：**

- 外部素材 → 取**姿势**，构图与你无关。
- 本项目成片 → 取**状态**，构图会污染这一镜（它自带那一镜的机位）。

两者都不提供构图，但原因不同，所以排除句也不同——混用是单条模式最常见的一处错。

**编号 = 上传顺序**，不是文件名。声明写错编号，整条提示词的槽位会全部反转，而画面"看起来好像也对"，极难发现。模板见 `references/reference-slots.md`；五类角色怎么认、放几张、撤哪张见 `references/slot-economy.md` 第零、一节。

### 阶段 2：需求归一化

把口语翻译成六个字段，缺的用默认值补齐，**不要反问**：

| 维度 | 从用户的话里取 | 取不到时的默认 |
|---|---|---|
| 主体与姿态 | 图里有什么 + 用户说的人称 | 沿用参考图 |
| 情绪弧型 | "越来越…"→上升；"事后"→衰减；"突然/反转"→转向 | 上升型 |
| 台词 | 用户给的句子（保留原语言） | 无台词 |
| 视觉档位 | 默认 3DCG；"三渲二"/"真人"按第三节切换 | 3DCG 档 |
| 镜头设置 | 镜数 0–20、角度档位 1–5 | 自动档 + 默认密度 |
| 规格 | "10 秒""竖屏""16:9" | 10 秒、9:16、768P |

**弧型是最容易漏的一步**，见 `references/physiology.md` 的三种弧型表。

### 阶段 3：字段映射

| 需求类型 | 落到 |
|---|---|
| 长相、发型、服装、非人特征 | 字段一，CHARACTER 段 |
| 姿势、朝向、距离、承重方式 | 字段一，POSE AND STAGING 段 |
| 情绪的过程 | 字段一，TIMELINE 段（时间码节拍） |
| 机位、焦段、运镜、焦点 | 字段一，CAMERA 段 |
| 台词 | 字段一，对应时间码内，`<d>[Chinese] …</d>` |
| 喘气、床响、布料摩擦 | 字段二 |
| 要不要 BGM | 字段三（不要也写 N/A） |

**用户给的情绪词怎么变成动作**——"僵硬""懵逼""尴尬""她好可怕"这类词，见 `references/performance-physics.md` 的映射表。**这是把表演写对的关键，不要自己发明动作。**

**空间不再从图里即兴推断。** 先按 `references/spatial-anchoring.md` 建账本：N# 节点 / P# 锚区 / K# 机位点 / c# 槽位 / 轴线 / 光位；再把 L1 写成地标句，L2 写成调度图 + 席位，L3 写成视线向量 + 在场者括号。`World:` / `Slots:` / `Shot:` 是 `POSE AND STAGING` 内部的写作顺序，不是新字段。

**写 CAMERA 前先选主设计支点**：高度、走位、空间、物件、光/声，哪 1–2 个最能讲清权力变化？主设计支点是高度就排高度阶梯，是走位就排 P#→P# 路径。没有设计支点，先看 `camera.md` 二b；不要直接填参数表。**少全景**：能用中景 + 人物移动 + 前景/背景交代空间，就不用全景。

### 阶段 3.5：设计预演（动笔前，不是可选项）

把演技、调度、镜头一起过一遍。

**演技**

- 他想要什么？谁挡着？他愿意为此做什么？
- 被碰到/被逼到/被看见时，身体先怎么反应？（局部→惊跳→定向→评估→对抗/顺从）
- 哪个部位先动：眼、眉、下颌、手？收在哪？
- 他的泄露是什么？他用什么遮盖？
- 听的人/旁观的人怎么反应？谁先动、谁不动？

**调度**

- 谁站/坐在哪？谁想靠近、谁想退开、谁不动？
- 谁先动、谁跟着动、谁不动？
- 谁从哪个 P# 走到哪个 P#？经过什么障碍？
- 谁被桌子/椅子/门/人挡住？谁有退路？
- 谁看谁？谁不看谁？谁知道什么？

**镜头**

- 主设计支点是什么：高度/走位/空间/物件/光声？
- 每一刀为什么存在？改变了权力/知识/立场/距离/尺度/节奏中的哪一个？
- 有没有不必要的全景？能不能用中景 + 人物移动 + 前景/背景代替？
- 最后一口画面是什么：结束，还是新秩序/新问题？
- 如果用户说"再设计一点"，会要求哪三处不同？现在就按那个标准想。

在脑子里比较≥2种排法：

- A：高度讲权力（低角王→高角虫）；
- B：走位讲权力（他退→她进→桌成陷阱）；
- C：物件讲权力（杯→礼物袋→椅→杯落地）。

选一个主设计支点 + 一个辅助；不要把所有招都塞进去。

三个底线：

- 至少一处**人物位移或刻意的静止**改变关系；
- 至少一个镜头用**中景/近景 + 人物移动或前景/背景**交代空间，而不是全景；
- 至少两镜之间变化的是**权力/信息/立场**，不只是景别。

不要为了设计而设计；如果全场必须静止，写出压力。这些思考不用写出来，它们只决定你写哪一句、排哪一镜、让谁先动。想清楚后一次写成——落笔时，你已经在脑子里比较过三遍。**不要把思考留到写完之后；落笔只有一条提示词。**

### 阶段 4：写提示词

按固定七段骨架写，顺序不要变：

```
CHARACTER → POSE AND STAGING → TIMELINE → CAMERA → PHYSIOLOGY PRIORITY
→ LIGHT AND ATMOSPHERE → CONSISTENCY LOCK
```

**TIMELINE 的节拍算法**：节拍数 = ⌈时长 ÷ 1.2⌉，末拍延长到 1.6–1.8 秒。一拍只推一件事，时间码首尾相接、累加等于时长。

写每一拍时同时落实四件事：

1. **表演**：可拍摄的微动作，不用形容词。
2. **机位**：高度 → 角度 → 焦段 → 运动 → 焦点；运动 ≤ 2 个且物理连续。
3. **空间**：人物在世界里的位置、朝向、接触点不因换机位改变。按三层写：`World:`（地标句，逐字复用）→ `Slots:`（调度图 + 席位 + 朝向）→ `Shot:`（本机位/景深/前景/帧内人数）；屏幕侧只在 `Shot` 或六段壳的 `subject_definitions` 里出现一次。
4. **档位锚**：风险镜就地重申档位关键特征（说话、近景、彩光、急停、接触、反打）。

现成骨架见 `templates/scene-10s.md`；单个镜头怎么运动见 `references/camera-motion.md`；镜头参数与构图见 `references/camera.md`；镜头之间怎么接见 `references/shot-continuity.md`。

### 阶段 5：自检与输出

**写前四检**（`spatial-anchoring.md` 2.4）：身份 / 拓扑 / 人数 / 轴线。四条不过，不写提示词。

```bash
node scripts/check_prompt.mjs prompt.txt --duration 10
# 剧集 / 批量：多个单元一起过闸，并比对系列常量块与入画清单
node scripts/check_prompt.mjs unit01.txt unit02.txt unit03.txt --series
```

`prompt.txt` 是自检用的临时工作副本，跑完删除，不算交付物；也可以 `node scripts/check_prompt.mjs --stdin` 直接从管道喂正文。默认交付仍是聊天里的代码块。

它查：段落完整性、时间码空洞/重叠/溢出、节拍数与时长匹配、`[Shot N]` 是否带 `At 00:0X.000`、CAMERA 段仰俯冲突、对白标记与语言标签、人数锁（肢体数量不检查）、否定式残留、多视图是否加了 `exactly one single figure`、**跨条引用**、**FACS/AU 编号泄漏**。`--series` 额外查**常量块是否被逐条缩写**（长度低于最完整那条的 85% 判失败，词面差超过 3% 给警告并列出差异词）与**六段壳的入画清单**（`retention_analysis` 声明的镜号 vs 正文实际出现的镜号）。

脚本判不了的三项必须人工过：**一拍是否只推一件事 / 生理层是否错开 / 有没有不可拍摄的形容**。设计层再加三问：**主设计支点是否在两个以上镜头兑现 / 每一刀是否有切因 / 少全景与人物位移是否做到**（`quality-gate.md` 设计闸）。完整验收再按 `quality-gate.md` 过三轮。

## 六、剧集模式：七步（顺序不能变）

**这一节回答**：一集怎么从资产到逐单元？**上游**：单条链路与规格；**下游**：每单元五步 + 2.5 设计预演。

用户要做一集多单元短剧时，**不要从读图开始**。完整版见 `references/series-workflow.md`。

> **前提（整套流程的地基）：H3 每次生成都是无状态的。** 它不记得上一镜谁站在哪、刀在谁手上、刚才说过什么。它只有两样输入：**这一次上传的图 + 这一串文字**。
>
> 三条直接后果：
> ① 输入里的记忆分两半：**图锚管"看起来是什么样"，文锚管"在哪里、到哪一步"**。参考图不是加分项，"额外锚定图"也不是"顺便参考一下画风"——它和文锚一起，才是跨单元记忆。
> ② 文锚不是配菜：地标句逐字复用、人物挂靠地标、物件状态链、动量接力、视线向量、在场者锁，每单元都要写。8 段 / 112 秒的案例零成片锚点跑完，靠的就是这一半（`text-anchoring.md`）。
> ③ 文字必须自包含：`still holding` / `same` / `as before` 这类短语在跨条时是空词（没有参照物）；`still` 必须与完整状态同句出现才成立，最稳是直接描述当前状态。每一镜都要重新陈述画面里所有关键物件（手上的刀、盖到胸口的被子、关着的门）。**这条在工程上的落法就是系列常量块**：每单元把同一份世界整块重写，不缩写、不"同上"（`text-anchoring.md` §2.8）。

```
1 项目规格      画幅/时长/视觉档位/风格锁原文/地标句/场面调度图/空间账本/调色/音频策略/镜头设置/交付形态  （一次定，全集复用；有座位、入口、桌面物件的室内戏，调度图与账本必填）
2 资产需求表    每张图只准提供什么 + 必须排除什么                （见 asset-production.md）
3 资产生成提示词 每张五段，第一句是同一段风格锁                   （一次给全）
4 出图并核对    差异对照表：假设 vs 实际                        （不许省）
5 反向修正      改身份锁 + 用资产里已有的特征改剧本钩子
6 单元编排      情绪曲线 + 钩子表 + 视角轮换表
7 逐单元写提示词 走 shot-intake.md：状态卡/空间账本 → 读图七项 → 定戏眼 → 2.5 设计预演 → 定视角 → 组装；第 0 步后先过四检
```

**用户已经带着资产来（"图我扔给你了，写一集"）时，七步裁成三步：**

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 读图 → 写规格卡 | **系列常量块**：风格锁 / 地标句 / 场面调度图 / 参考映射 / 主体定义（`text-anchoring.md` §2.8）。场景图按 §2.2 的五步读地标，没拍到的面自己补死 |
| 2 | 核对 → 反向修正 | 图上没有的特征从身份锁里删掉；图上真实存在的细节升级成钩子 |
| 3 | 逐单元或批量出提示词 | 每单元整块重写常量块 + 本单元空间复述 + 首拍接力 |

跳过的是"资产需求表 / 资产生成提示词 / 出图"——用户已经做完了。**核对与反向修正不能跳**，那是唯一一次把文字对齐到图上的机会。

### 批量与逐轮：什么时候一次给 N 条

用户一次要多个单元（"写一集""接下来 6 个单元"）→ **批量**；只说"下一个镜头"→ **逐轮**。下面四种情况即使要一集，也必须先逐轮：

| 情况 | 为什么必须逐轮 |
|---|---|
| 承重或多点接触（拥抱、打斗、扶持） | 接触点靠文字写不准，要看上一镜成片 |
| 服装 / 道具出现不可预测形变（撕裂、湿透、沾血） | 形变后的状态只能从画面读 |
| 光发生剧情性变化（烛火熄灭、门被推开、灯关掉） | 新光向要从画面确认 |
| 用户明确说"先出一条看看" | 他要先评估方向 |

批量交付的形状：

```text
【规格卡】系列常量块（一次给全）
【单元 01】…【单元 0N】每条自包含，可单独粘贴
```

**批量不等于省掉常量块。** 用户是一条一条粘进 H3 的，模型看不到你上一条写过什么——每一条都要把五件常量整块重写，状态不进块内。

### 七个决定成败的点

**其一，资产必须先行。** 先写提示词再去凑图，会撞两个死结：你写的身份特征图上不存在；你写的空间关系图上不成立。先定资产，提示词就是"描述已有之物"，命中率高一整个量级。

**其二，身份卡永远是立姿，不是剧情姿势。** 用户说"她侧躺在床上的样子"要作为身份卡时，要主动纠正：**姿势交给提示词的 `POSE AND STAGING`，身份卡只负责脸和衣服**。锚点图带姿势，后面每一集都要花力气压它，而且压不干净。

**其三，出图之后必须核对，且差异要反向写回剧本。** 写了"虎口的疤"而实际资产没有，就不能继续用这个疤做伏笔——换成资产里真实存在的特征（比如颈侧的痣）。用不存在的特征做钩子，第 5 集无解。核对表与案例见 `references/asset-production.md`。

**其四，成片锚点只留最新一张。** 两份成片记录的是两个不同时刻的空间关系，一起传会让模型取中间值。每换一个单元，上一张成片退场。规则见 `references/slot-economy.md`。

**其五，文字也要锚定，不能只靠成片。** 成片锚点只记录一个机位；换一次视角，图里的空间关系就不可读了。地标句（3–4 个固定地标，竖屏 2–3 + 固定顺序 + 光向）逐字复用，人物位置永远挂在地标上，再配动量接力、物件状态链、视线向量与在场者锁，才能在零成片锚点时也不漂。8 段 / 112 秒的案例就是这么跑完的。规则见 `references/text-anchoring.md`。

**其六，地标句锁环境，锁不住座位。** 食堂、教室、审讯室、长餐桌这类"有家具、有座位、有人进出"的室内戏，地标句之外还必须写一张**场面调度图**：固定结构（墙 / 窗 / 门 / 柜台 / 通道）、固定席位（谁坐哪张桌的哪一侧、面朝哪）、入口与回廊、桌面物件位置。它不是第六把锁，是地标句的加深层，写在同一处常量区，不占槽位。**就座多人对话不是"简单场景"**——不写调度图，三个单元就会有三种坐法。规则见 `references/text-anchoring.md` §2.7。

**其七，常量块每单元整块重写，不许缩写。** 八个单元接起来像一条，靠的不是模型记得，而是每条提示词里都装着一份完整的世界：风格锁、地标句、调度图、参考映射、主体定义，一字不改地重写一遍；状态不进块内——臂章歪没歪、包扣开没开、刀在谁手上，写在 `POSE AND STAGING` 与 `CONSISTENCY LOCK`。缩写成"同上"、"沿用前一条"，等于让模型自己补世界——它每个单元都会补一个不一样的；把"她手里端着缸"留在块里，则会"逐字一致地过时"，模型同时看到"她端着"和"缸在桌上"。判据：遮住动作部分，任意两条的常量块必须逐字相同。规则见 `references/text-anchoring.md` §2.8。

### 每次换单元前必须回答的五个问题

```text
1 上一镜结束时，每个人在哪块地标旁？（用地标句里的名字；主光方向一并报出）
2 上一镜结束时，谁手上有什么？东西现在在谁身上、哪个位置、是开是合、鼓还是瘪？
3 上一镜最后一拍的力停在哪一步（蓄力 / 悬空 / 半程 / 余波）？这一镜第一拍怎么把它接上？
4 这一镜谁看谁、朝哪个屏幕方向、多高、多远？换视角后两条视线还相交吗？
5 画面里每个不说话的人在哪、嘴什么状态？这一镜换视角吗，换成什么，带来六种新信息里的哪一种（新主体 / 新空间 / 新状态 / 新视角 / 新阶段 / 关键反应，见 `shot-continuity.md` 第一节）？
```

答不上来，不许动笔。

**答完五问，再做四检**：身份 / 拓扑 / 人数 / 轴线（`spatial-anchoring.md` 2.4）。五问确认"接得上"，四检确认"没写乱"。

### 接续模式：三选一，混不了

H3 里**参考图模式与首尾帧模式互斥**。

| 模式 | 传什么 | 用在哪 |
|---|---|---|
| A 参考图 | 场景空镜 + 角色锚点 2–3 张 | 机位跳变、换视角 |
| B 尾帧 | 上一镜成片最后一帧作首帧（**不能再带参考图**） | 同一条镜头拆两段生成，成片里无剪辑点；接缝必须遮挡 |
| C 参考图 + 成片锚点 | 场景 + 锚点 + 上一镜成片 | 剧集的主力做法 |

**判断法：动作连续走 B，机位跳变走 A/C。**

尾帧截取：截最后一帧、**往前退 0.2–0.3 秒**（成片比请求多 0.5–0.6 秒）、存 PNG、不缩放。

**文锚与三种模式正交。** 不管走 A、B 还是 C，五锁每单元都写：地标句逐字复用、上一单元末拍接力、物件状态链复述、视线向量校验、在场者锁。模式只决定"传不传图、传哪张"，不决定"写不写文锚"。

## 七、硬规则

**这一节回答**：H3 的能力边界是什么？**上游**：总纲二；**下游**：所有镜头 / 表演 / 台词写法。

**失败模式不是另一套规则，是链的断点。** 身份断、空间断、表演断、镜头断、台词断、声音断。先回上游，不要在下游硬修（`failure-modes.md`）。

### 7.1 先记这四条：H3 的能力边界（优先级高于下面所有通则）

这四条不是风格偏好，是模型特性决定的。前三条违反了会让成片"看起来廉价"，第四条违反了会让画面"看起来假"。

0. **信任它的空间理解，不要过度设防。** H3 是旗舰级视频模型：多角色同时反应、身体重心转移、视线锁定、复杂的双人互动，它都处理得了，**不会凭空多出一条胳膊或者把肢体融化**。所以一致性锁只写"人数 + 状态 + 惯性 + 身份标志物"，**不写 `two arms` / `ten fingers` / `two legs`**。
   > 这条排在最前面，因为它是一种心态。担心它崩，就会在锁里堆一堆"不要变形"，而这些词占掉的正是本该用来描述动作和空间的注意力预算。**写得越具体它越准，防得越多它越保守**——保守的成片就是"一个人在动，其他人在等指令"，比肢体崩坏更假。
   >
   > 唯一的例外：某个项目**实测**在这一处崩过，才针对性写一次，而且只写崩的那一处。

1. **相邻单元绝不同构图。** 单元是独立生成的，同一构图的两次生成必然有微差（脸的角度、光的强度、布料褶皱）。单看每段都没问题，**但两段剪在一起观众会看到画面"跳"了一下**——这是短剧里最容易被察觉的廉价感。规则：**四根骨架（景别档 / 轴线侧 / 主体位置 / 入画人数）至少换一根**，判据是"两张截图并排，闭眼都能看出不一样"；平视改微侧五度、焦段 50 换 55、机位升高十厘米这类参数微调不算换骨架。
   > 这也是成片锚点必须写 `copy zero of its framing and zero of its camera position` 的真正原因——不写，模型会连机位一起抄走，于是这一单元变成上一单元的翻拍，正好撞上这条。
   >
   > **唯一例外是 B 尾帧接续**：同一条镜头拆两段生成、成片里没有剪辑点，构图必须连续，接缝用前景遮挡 / 甩镜 / 闪光 / 快速动作藏住。一旦打算当切点剪开，就回到本条。细则见 `references/shot-continuity.md` 第零节。

2. **景别跟着"要不要读脸"走，不是跟着配额走。** H3 的脸部可读性随景别衰减：大特写/特写最锐利 → 近景锐利 → 中近景稳 → **中景变软但仍然可读** → 全景/远景只剩轮廓。
   - 判据一句话：**这一镜需要观众读到脸上的信息吗？** 需要（台词、眼神变化、微表情、情绪转折）→ **中近景以内**；不需要（氛围、位置、气势）→ 中景到全景都可以，**而且全景往往更有力量**。
   - **全景不是禁区。** 剪影、背影、逆光里的轮廓，这些镜头不存在"糊脸"——因为本来就不需要读脸。巨大月轮下的人影、门缝里的全身、雨中的走远，远景正是最优解。
   - 三条仍要守：**主角第一次出场在近景以内**；**情绪转折点不用全景**；**长台词不放中景以外**。

3. **场景图是三维地图，不是取景框。** 它提供房间结构（墙、门、窗、家具、光从哪来），**机位由这一单元自己定，可以放在房间任何位置**。声明里写 `the camera position for this shot comes entirely from the CAMERA section below`，再用一句话把机位钉在房间的具体位置。不写，模型会退回参考图的视角，于是所有单元都是同一个角度。**但它是拍摄弧，不是 360°。** 未见墙面不假设；反打补一张反方向环境卡，或让背景保持近景虚化。**没有俯视图时，按 `spatial-anchoring.md` 3.1b 从场景图读节点表；不要要求用户补俯视图。** **场景图不是构图参考：第一镜不得复用场景图的机位，相邻镜头优先换高度/角度或轴线侧。**

### 7.2 再记这十四条通则（按出错频率排序，前五条违反了提示词基本报废）

1. **每个 `[Shot N]`（N≥2）必须带 `At 00:0X.000, the camera cuts to ...`**——紧跟在标签后，或写在标签前，两种都接受。只写标签不写时间码，切点会晚 1–2 秒。
2. **时间码首尾相接，累加等于时长。** 有洞 → 空白帧；重叠 → 动作打架。
3. **台词只放在脸可见的镜头，且该窗口镜头必须静止、焦点锁死。** 窗口里不要同时安排动作——让他停手说话，说完再动。
4. **一致性锁必须在最后一段，写人数 + 状态 + 惯性 + 身份标志物。** `keep the pose` 无效；`her weight stays on her front foot, her spine tilted two degrees forward` 有效。**不写肢体数量锁**（详见 7.1 第 0 条）。
5. **H3 没有负向分支。** `no` / `不要` / `禁止` 不会压制概念，可能被正向采样。全部改成可见的确定状态。用 `zero people` 而不是 `no people`。
6. **`non_diegetic_music` 必须写。** 不想配乐也要写 `N/A`，否则模型自己补一段，且音量不小（实测差 25 dB）。
7. **一拍只推一件事。** "坐下 + 脸红 + 抓床单"是三拍，写成一拍三样都只做一半。
8. **镜头运动 ≤ 2 个，且两个必须物理连续**（推+仰可以，推+绕+摇不行）。CAMERA 段不许出现两套矛盾的机位（仰拍 + 俯拍同时写，画面会跳四个机位）。
9. **跨风格必须三件套**：槽位排除旧渲染 + 镜头首句钉死目标风格 + 细节处复述风格。缺一个就会"动漫脸配真人毛孔"。
10. **画面内可见文字加英文双引号。** 不加引号的招牌字几乎全部变乱码。
11. **一个空间事实只准有一个主人。** 世界拓扑归地标句/账本，身份归主体定义/c#，屏幕侧归本镜投影；同一事实写两遍不是加强，是给模型两个版本。屏幕侧只在本镜投影出现一次；retention / 状态卡如引用不改值。**状态从成片，拓扑从账本。**
12. **正反打的肩侧 = 视线侧。** 焦点人物看向前景肩所在的那一侧；A/B 两行相反；手性开场定一次，整场不改。换侧必须靠切，不在一个镜头里漂移。
13. **人数分三级。** 房间总人数（账本）/ 帧内人数（本镜）/ 进出事件（时间码）；画外的人不传身份卡，出画不等于离场。
14. **多人场景优先机位移交。** 一次生成内从 A 的肩后推/弧线到 B，路径不跨轴；台词窗口前必须停稳；起幅/落幅人数各自写死。

### 7.3 再记三条：设计（2026 升级）

1. **少全景。** 能用中景 + 人物移动 + 前景/背景关系交代空间，就不用全景；全景只给三种情况：空间规模/孤立/命运、人物变成图案、开场/收场需要社会关系图。人脸在远景里最容易崩。景别判断仍以 7.1 第 2 条为准：需要读脸时中近景以内。
2. **人物要移动。** 至少一处人物位移或刻意的静止改变关系；镜头可以不动，让人物在画框里移动。没有走位的镜头，要么是刻意的静止（僵住/权力），要么是 coverage。写法：起点 P# → 路径 → 阻力 → 终点状态 → 声音（`camera.md` 二b）。
3. **每一刀要切因，每一镜要新信息。** 每刀至少改变权力/知识/立场/距离/尺度/节奏之一；两镜做同一件事，删一个。切碎不是同高度多切几刀，是切成更多权力状态。

### 7.4 导演层硬条款

这些条款与 7.1/7.2/7.3 同时生效；冲突时 H3 格式与能力边界优先。

- **每次打击都有明确接触。** 不以"激烈对打/拳脚相撞/兵器碰撞"代替具体动作。空手写清谁的哪侧拳、肘、掌或脚，接触对方哪侧、哪个部位；兵器写清双方持握手、各自参与接触的段位与表面，以及共同接触区域。瞄准部位与实际命中或格挡部位分别表达；落空写清经过哪里、如何避开。切镜保留同一次接触，不能换部位、重复命中或在未接触处出现冲击。
- **运动变化必须可推导。** 向右飞、上升、下落、翻滚分别描述平移轨迹与姿态；换机位、俯拍或身体朝下都不是运动转向。下镜先继承切点处的运动，再发生有原因的变化；重力可以让轨迹下弯，但不会因切镜消除水平速度。
- **默认维护连续性。** 世界方向、角色自身左右与画面左右分开记录；每个连续切点必须有「前镜末态 → 后镜初态 → 新变化」的具体依据。只有用户明确要求破坏连续性时才设计此类效果；可见走位形成新轴时，让观众看懂。
- **跨单元一致性按输入类型选锚，不默认双锚。** 有连续成片用双锚（成片只留最新一张）；只有静态资产图用资产锚 + 文锚；**用户只给文字时走纯文锚严格模式**，空间全部由文字写死。图锚管外观与上一刻的可见状态；文锚管坐标、动量、物件、视线与在场者。换视角时必须写全地标句 + 人物挂靠地标 / 席位 + 视线向量；**室内有座位、入口、桌面物件时必须写场面调度图**，席位用"哪张桌 + 哪一侧 + 面朝哪"写；不得用"A 在 B 左边"这类相对坐标，也不得用 `as before` / `previous shot` 代替当前状态描述。**多单元时把风格锁 / 地标句 / 调度图 / 参考映射 / 主体定义压成系列常量块，每单元整块重写，状态不进块内。** 详见 `text-anchoring.md` §2.7、§2.8、§8.2、§10.1。
- **武器结构是硬约束。** 每件刀剑只有一个柄、一片连续刃身和一个远端尖部；手始终握柄；正握、反握、转腕和换机位都不互换柄刃，不生成第二个柄、第二个尖部、分叉或第二把实体武器。双面开刃不等于双头。任何持械画面先锁连接关系。
- **构图服从实际距离。** 几十米、一千米按原值保留；同框必须兑现尺度，切近景不缩短世界距离，地平线不是人物吸附线。详见 `camera.md` §七。
- **表演写可拍摄的物理动作。** 不写"她感到""气氛变得"；情绪词按 `performance-physics.md` 映射为力、反作用物与中间态。情绪词后跟 `micro expressions` 收窄幅度，再按部位 + 顺序给出一条可见动作链；台词前留半拍准备、台词后留半拍余韵，不说完就"断电"。真人档每个 3–4 秒的关键近景/特写写 3–4 个有序微节拍（它与 TIMELINE 时间码节拍是两套计数，见 `acting-performance.md`「克制 ≠ 少写微表情」）；泪膜、单滴、湿润泪痕三态跨镜继承。**对白戏再加三条**：话轮不是排队、失语落在最难面对的词上、三股力量（LEAK / CONTROL / CARE）同时存在（`dialogue-performance.md`）。
- **特效强度由结构支撑。** 主形、传播、作用对象和结果先可读，再细化卷涡、碎屑与高光；避免均匀撒点、全程等亮、所有材质同样炸开和只在画面表层漂浮。用户规定的环形、对称、霓虹、无烟、无破坏等设计保留。
- **视觉档位绝不混用。** 三档词条互斥；FACS/AU 编号只作内部推导，**绝不写进提示词正文**。
- **用户显式设置优先。** 镜数、角度档位、时长、画幅、视觉档位、指定拍法（全景长镜、全程正常速等）都高于技能默认；冲突时指出具体矛盾，不暗改。

## 十、输出格式与交付

**这一节回答**：交付长什么样？**上游**：全部；**下游**：用户。

默认按这个结构交付，不要写成方案分析：

1. **一句话戏眼**——这一单元最值钱的那一秒是什么（"最后两秒她被锁在门口，笑垮在眼睛里"）。用户靠这一句判断方向对不对，**没有它，后面的提示词他没法评估**。
2. **一句关键决策**——主设计支点 + 为什么这样拍（"走位版：他退到餐桌、她跟进，桌子变成陷阱"）。
3. **素材分工表**（发图时）：编号 / 职责 / 排除；有素材媒介冲突时单独说明。
4. **节拍表**——三列：`| 秒 | 镜 | 发生什么（这一拍改变了什么）|`。每拍后面用括号补一句改变了权力/信息/立场/距离中的哪一项。这是给用户看的执行方案，让他能在生成前就判断节奏对不对。
5. **提示词**：一个英文代码块，单段可复制，内部七段全大写标签。
6. **参数建议**：duration / resolution / ratio 三行。
7. **崩点表**：3 条左右，只写这条特有的，每条给"症状 → 修法"。
8. **一句"如果不对，先改这三处"**——具体到句子，不要泛泛而谈。

**剧集模式的交付差异**：

- 第 1 步交付资产清单 + 每张图的生成提示词，**一次给全**；用户已经自带资产时，改为交付**规格卡 + 系列常量块**。
- **逐轮**：第 4 步之后，每轮一条视频提示词 + 上传顺序 + 3 条崩点。
- **批量**：用户要一集且不触发逐轮条件（第六节的四种情况）时，一次交付规格卡（常量块）+ 单元 01–0N，每条自包含、可单独粘贴；素材分工只在规格卡里写一次。
- **不写文件**，直接在对话里给代码块（用户要复制的是提示词，不是文档）；除非用户明确要求归档。
- 每轮（或每批开头）用一两句说清"这一镜的戏眼在哪 + 主设计支点是什么"，这是用户判断方向对不对的唯一依据。

**文件交付**（用户要求归档时）：`H3-片名-版本.txt`（片名未给就用项目短名或 `未命名`），UTF-8，只含提示词，无标题、代码围栏、自检与中文翻译附录；回复里给链接、实测字符数与简短来源/采用点。压缩顺序：全局重复 → 同义修辞 → 无必要技术参数；**不删**动作因果、接触证据、交接状态、声音时序、参考关系。

语言：**提示词正文英文，其余中文。**

### 维护纪律

- **一条规则只写一处，其他文件只引用。** 同一件事在 `SKILL.md` 和 `references/` 各写一份，改的时候必然漏一处，然后两处互相矛盾。写新规则时先问：这条的唯一事实源放在哪？
- **改完必须用"没有上下文的 agent"盲测。** 起一个不读本对话的 subagent，只给它文件路径和一段用户口语（不给任何背景），要求它回答"这几张图分别该怎么派活""该传几张""这是哪种衔接类型""该不该加载特效模块"。规则默会写在脑子里时，写出来的句子只有知道答案的人才读得懂。
- 新案例先进 `references/case-studies.md`，再从案例提炼规则回填。**先有案例，后有规则。**
- 改自检项时同步改 `scripts/check_prompt.mjs`，否则机械检查会静默失效。
- H3 版本更替只改 `references/h3-output-spec.md` 的语法与参数段，七段骨架和六层生理不动。
- 词库只收**可拍摄的物理描述**。"她感到""气氛变得"一律不入库。
- Ref2VA 的枚举词与四类标签是**接口契约**，不随案例改动。
- 视觉档位、表演、连续性、特效、审美等导演层规则，改动时同步核对 `quality-gate.md` 的对应闸门与 `sources.md` 的依据边界。
- **剧集七步与每单元五步的顺序是硬约束。** 任何"加快"的冲动都要问一遍：跳过的是哪一步，代价是什么（见 `series-workflow.md` 第六节）。
