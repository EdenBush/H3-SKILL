# JSON 模式：ComfyUI 节点的封装与转义

默认交付是纯文本，直接粘贴即可。只有当调用方（例如 ComfyUI 的提示词改写节点）明确要求两字段 JSON 时，才用这套封装。

---

## 一、目标格式

```json
{"expanded_caption":"COMPLETE_DESCRIPTION","target_aspect_ratio":"16:9"}
```

两条硬约束：

| 项 | 要求 |
|---|---|
| 键 | 恰好两个：`expanded_caption`、`target_aspect_ratio`，都是字符串 |
| 外部 | 不许代码围栏、不许说明文字、不许额外键、不许推理过程 |

`expanded_caption` 内部：

- 一整段，**不能有真实换行**
- 不写结构标题、项目符号、章节名
- 不含推理或元评论

---

## 二、转义

`expanded_caption` 内部如果出现 ASCII 双引号 `"`，必须序列化成 `\"`。

但按本技能的写法，**正文里的文字一律用单引号包裹**，所以正常情况根本不该出现需要转义的双引号。这是设计上的取舍：从源头消除转义问题，比事后修补可靠。

反斜杠同理，出现时必须写成 `\\`。

---

## 三、写 JSON 的两个安全做法

**做法一：先写纯文本，再转换（推荐）**

1. 先按默认格式把描述写完（一整段，无换行）。
2. 用脚本转义并封装：

```bash
node scripts/check_caption.mjs caption.txt --json --ratio 16:9 --wrap
```

`--wrap` 会输出可直接使用的两字段 JSON，并顺手校验。

**做法二：直接写 JSON**

手写时注意：

- 整个 JSON 只占一行（或让 caption 值保持单行）
- 键名顺序无所谓，但建议 `expanded_caption` 在前
- 写完用 `JSON.parse` 验一次，或跑脚本

---

## 四、画幅字段

`target_aspect_ratio` 的取值规则见 `references/aspect-ratio.md`。要点：

- 用户给了具体比例 → 原样照抄
- adaptive 模式 → 主参考比例，或按需算出的最简整数比
- 永远不输出 `adaptive`
- 格式 `W:H`，无空格，最简整数比

---

## 五、校验清单

- [ ] 整体能被 `JSON.parse` 解析通过？
- [ ] 恰好两个键，都是字符串？
- [ ] `expanded_caption` 内没有真实换行？
- [ ] 内部双引号是否都已转义为 `\"`（或者根本没用双引号）？
- [ ] `target_aspect_ratio` 是 `W:H` 最简整数比，不是 `adaptive`？
- [ ] 没有代码围栏、没有前后说明文字？

---

## 六、常见失败

| 现象 | 原因 | 修法 |
|---|---|---|
| 节点报 JSON 解析失败 | caption 里有真实换行 | 合并成一行 |
| 文字显示成乱码 | 双引号没转义，或者用了会破坏 JSON 的字符 | 改用单引号包文字 |
| 解析成功但描述被截断 | 某个 `\"` 写成了 `"` | 用脚本重新封装 |
| 画幅字段变成 `adaptive` | 直接透传了用户选择 | 按规则算出具体比例 |
